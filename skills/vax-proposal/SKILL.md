# 입찰 제안 하네스 (재료 팩 → 게이트 → 초안 → 덱)

대표의 `/bid-loop`(P1~P6 게이트 · `_STATE.md` 상태 기계)를 뼈대로 삼고, 판단·문장·디자인은 사람 곁의 Claude가 맡는다.
회사 팩트·실적·인증·숫자는 **재료 팩에 있는 것만** 쓴다. 없으면 만들지 않고 `⚠️ 확인필요`로 남긴다. 제안서 문장은 그대로 발주처에 가므로 추측이 가장 비싸다.

규칙 문서는 셋이다. **문장은 `references/writing.md`, 슬라이드는 `references/deck.md`, 채점은 `references/review-rubric.md`.**
나머지 파일은 계약(`material-pack.md`)·서식(`staffing-table.md` · `reference-index.template.md`)·절차(`images.md` · `figma-howto.md`)·금지 목록(`guardrails.md`)이다.
(2026-09-05: 규칙 파일 12개를 이렇게 줄였다. 하루에 규칙을 여덟 번 덧붙이자 덱 46장이 한 얼굴이 됐기 때문이다. 규칙을 더하기 전에 기존 규칙을 하나 뺄 수 있는지 먼저 본다.)

## 언제 쓰나
- "R26BK0123 제안 진행해줘", "이 공고 가점 진단부터", "/bid-loop 몽골유적", "재료 팩 여기 있으니 초안 써줘"
- **아닌 것**: 견적서·회사소개서·공문·입찰증빙 같은 **완성 서식**은 `vax-exit-kit`(하류)이 한다.

## 두 가지 실행 모습
- **대화형**: 게이트마다 결과를 보여 주고 동의를 받으며 진행한다.
- **루프형(`/bid-loop`)**: `loops/bid-loop/bid-loop.md`의 운행 규칙대로 **1회 호출 = 1스텝**. 첫 동작은 `_STATE.md` 읽기, 끝나면 갱신 후 즉시 종료.
  헤드리스에서는 묻지 않고 `차단사항`에 적고 끝낸다. 이 파일은 단계의 **내용**을, bid-loop.md는 **운행**을 맡는다.

## 절차 (순서를 바꾸지 않는다)

### P0 · 재료 팩
1. 공고번호로 Notion 입찰레이더의 공고 페이지를 찾고 자식 페이지 **「📦 제안 재료 팩」**과 **「📄 RFP 원문(추출)」**을 읽는다(`notion-search` → `notion-fetch`).
   두 페이지의 「판본:」 도장이 같아야 한다. 원문은 `00_RFP원문_추출.md`로 저장해 다음 스텝에서 다시 읽지 않는다.
2. 재료 팩이 없으면 멈추고 알린다. **재료 없이 초안을 쓰지 않는다.** 사용자가 본문을 붙여넣으면 그것을 쓴다.
3. `material-pack.md`의 H2 열 개(0~9)가 다 있는지 본다. 빠진 항목은 `⚠️ 확인필요`로 다룬다.
4. 사업 폴더 `bids/{사업명}/`을 만들고 `loops/bid-loop/_STATE.template.md`를 `_STATE.md`로 복사한다.

### P1 · 평가표 검산 → `01_평가표.md`
재료 팩 §0~§4를 **원문 표현 그대로** 옮긴다. 없는 항목은 `[RFP에 명시 없음]`. 기술:가격 비율, 정량·정성 배점표(항목·배점·만점 조건·증빙), 참가자격, 과업 산출물 개수.
§7에 **제안서 작성 규칙**(`deck.md` §1: 지정 목차·분량·용지·쪽번호·문체·빈 항목·특화사항·참고문헌·별지·발표)을, §8에 **RFP 요구사항 ID와 장비·산출물 품목 전부**를 하위 항목까지 번호 매겨 둔다.
**출구**: 정량·정성 배점 합이 100. 안 맞으면 누락이니 재료 팩 §2를 다시 본다.

### P2 · 가점 진단 — 게이트 ① → `02_가점진단.md`
정량 항목마다 재료 팩 §5·§6을 대조해 실점을 센다. 단계별 점수표(신용등급 평점·실적 건수·지체상금)는 **재료 팩 §2 끝의 원문 표**를 쓴다. 표준표를 기억으로 쓰지 않는다.
회사 상수(신용등급·업종코드·직생·설립일·특례 요건)는 **재료 팩 §5에서만** 읽는다. 어느 파일에도 박지 않는다.
실적 건수형은 색인 군집에서 조건에 맞는 실적을 표로 세고, 증명서 발급 가능한 공공기관 직접 계약을 먼저 센다. 근거 없는 항목은 「확인필요」로 두고 0점으로 가정하지 않는다.
실점을 **회복가능**(마감 전 서류로 0 가능)과 **회복불가**(신용등급·매출·업력)로 나눈다. **창업기업 특례는 선행 조건**이다. 공고에 조항이 불명확하면 발주기관 질의를 `차단사항`에 올리고 종료한다.
```
실점합계 ≤ 5.0                           → 통과 → P3
실점합계 > 5.0 AND 정성배점비중 ≥ 70%     → 사용자 판단 요청, 종료 (정성으로 역전 가능 — 자동 폐기 금지)
실점합계 > 5.0 AND 정성배점비중 < 70%     → 중단(가점미달). 실점 원인·회복가능 처리안 보고
회복가능 실점                              → 합계에 넣되 `차단사항`에 마감 역산 기한과 함께 등록
```
서식: `| 정량항목 | 배점 | 우리 해당 | 획득 | 실점 | 구분 | 근거(재료 팩 §) |`

### P3 · 레퍼런스 → `03_레퍼런스매핑.md`
재료 팩 §5·§7과 `reference-index.template.md`의 구조(기술요소 ↔ 실적 ↔ 재활용 문구)를 쓴다. 비어 있으면 위키 「레퍼런스 색인」(https://app.notion.com/p/3d16394f4c9981b493e3d4b5dc7884a9)을 직접 읽는다.
과업을 기술요소로 분해 → 요소마다 실적(발주기관·사업비·기간·역할) → 실적요건 충족 조합 → **약점도 기록**(`[레퍼런스 공백]`, 대체 근거를 R&D·특허·인력에서 찾고 없으면 공백).
**출구**: 매칭 3건 이상 AND 공백이 기술요소의 1/3 이하. 미달이면 다른 각도로 1회 재탐색, 2회 연속 미달은 보고 후 종료.
서식: `| 기술요소 | 매칭실적 | 발주기관 | 사업비 | 강점 문구(그대로 쓸 문장) |`

### P3.5 · 페인포인트 → 색채 카드 → 아이디어 → 방향·전략 → `03a_페인포인트.md` · `03b_방향전략.md`
한준 2026-09-05 "3가지에 집중": 이 스텝이 그 셋 중 둘(페인포인트·색채)을 만든다. `writing.md` §2·§3·§5를 순서대로.
1. **페인포인트**(`writing.md` §2): RFP 배경·목적의 고유명사를 출발점으로 기관 홈페이지·보도자료·전년도 같은 사업·감사/회의록·상위 계획·이용자 목소리를 웹에서 읽는다(`deep-research` 활용).
   「RFP 문장 ↔ 확인한 사실(출처·날짜) ↔ 숨은 필요」 5~8줄을 `03a_페인포인트.md`에 쓴다. **배점 항목에 연결되지 않는 관찰은 버린다.** 「RFP에 없지만 발주처가 원하는 것」 셋을 따로 뽑는다.
2. **색채 카드**(§3): 재료 팩 §5·§7과 위키 색인에서 이 공고에 닿는 우리 자산을 실물·등록·실적·사람·방식 다섯 종류로 8~15장. 카드마다 「경쟁사가 못 쓰는 이유」 한 줄. 못 붙이면 카드가 아니다.
3. **아이디어**: 페인포인트 × 카드 교차표에서 열 개 넘게 만들고 셋을 고른다(배점 · 예산 · RFP에 없는 필요 · 경쟁사 모방 불가). 「요구를 더 잘 하는 방법」과 「값을 올리지 않는 추가 제안」 두 갈래.
4. **방향**(§5): **돈 → 안 할 것 → 할 것 → 쓸 강점** 6~10줄 → **사용자 동의** → 컨셉 한 줄(상위 페인포인트 + 카드) · 차별점 3개 이내(범주 다르게) · 항목별 대응 · 리스크. 모든 주장 옆에 근거(재료 팩 § · 페인포인트 # · 카드 #).
루프형이면 방향을 `_STATE.md`에 적고 다음 스텝에서 이어 간다.

### P4 · 초안 + 검토 → `04_제안서_v1.md` … `v4`
`writing.md` §4(쓰는 순서: 기억할 문장 하나 → 말로 먼저 → 구체에서 시작 → 한 사람 시점 → 소리 내어 읽기)와 §6을 따른다. 마크다운으로 쓴다(HTML·docx·pptx는 이것을 렌더한 결과). 투입인력 장은 `staffing-table.md` 구조에 위키 인력 데이터를 채운다.
비교·대조·순서·수치·일정·체계는 문단 아래 ```fig 블록으로 지정한다(`deck.md` §3). `python3 scripts/figures_svg.py 04_제안서_vN.md --list`로 세어 절과 대조한다.
검토마다 **먼저 `python3 scripts/proposal_lint.py 04_제안서_vN.md`를 돌린다**(정규식 검사 · 어느 기계에서나 같은 답). 「상」이 있으면 다음 회차로 못 간다. 결과를 `logs/lint_N.txt`로 남기고 비판자에게 넘긴다.
검토는 관점을 다르게 세 번: ① **누락** — `01_평가표.md` §8의 요구 ID·품목을 하위 항목까지 한 줄씩 대조(대응 없으면 「해당사항 없음」이라도 명시)
② **증거** — 근거 없는 문장·빈 수사·출처 없는 발주처 사실 ③ **차별성** — `writing.md` 점검표(페인포인트·색채·문장 세 축)를 `logs/검토3.md`에 채운다. 회사명 가림을 통과 못 한 문단이 있으면 고친다.
④ **비판자** — `proposal-critic`(mode text)를 별도 컨텍스트로 부른다. 회차마다 `v{N+1}`을 새로 만들고 `logs/검토{N}.md`에 남긴다.
분량이 크면 챕터 단위로 쪼개고 `다음행동: P4-초안(3장부터)`처럼 재개 지점을 남긴다.

### P5 · 심사위원 채점 — 게이트 ② → `05_심사결과_N.md`
`review-rubric.md`를 그대로 따른다. 페르소나 고정, **감점 사유를 먼저 전부 쓴 뒤 점수**, 항목마다 제안서 안 근거 위치 인용(못 하면 0점), 배점은 `01_평가표.md` 정성 배점의 100점 환산.
```
총점 ≥ 80                      → 통과 → P6
총점 < 80 AND 재작성횟수 == 0   → P4-재작성 (개선 우선순위 상위 3건만. 전면 재작성 금지)
총점 < 80 AND 재작성횟수 == 1   → 중단(심사미달). 사람이 판단한다
```
80점은 합격선이 아니라 **착수선**이다.

### P6 · 슬라이드 계획 → Figma
`deck.md`를 따른다. 고정은 §4 여섯 가지(발주처 CI 팔레트·글꼴 가족·헤더·쪽번호·사진 출처·내부 표기 없음)뿐이고, 레이아웃·위계·도식 형태는 덱마다 Claude가 정한다(한준 2026-09-05 "디자인·레이아웃 자율").
순서: ① `01_평가표.md` §7의 RFP 규칙 → ② 제목 사슬 → ③ 초안 문단 전부 배치(요약 금지) → ④ RFP 요구 ID 대응표 → ⑤ **디자인 브리프**(시각 컨셉·팔레트·글자 단계·레이아웃 가족·여백 장·헤더 좌표, `deck.md` §5) → `07_슬라이드계획_v1.md`
→ ⑥ `python3 scripts/proposal_lint.py 07_슬라이드계획_v1.md --plan`(「상」은 RFP 관련만: 제목 사슬 절·장별 표·문단 번호 열·대응표 빈칸. 브리프·연속 유형·가리키기 제목은 「중」 — 경향) → `proposal-critic`(mode deck) → ⑦ 사진 목록·발주처 CI(`images.md`)
→ ⑧ **한 장 시안**을 만들어 화면을 찍어 사용자 확인(`figma-howto.md` — Figma 공식 `figma-use-slides` 스킬을 먼저 읽는다) → ⑨ 행 단위 제작, 행마다 `validate()` → ⑩ **전 장 화면을 찍어 비판자에게 다시**(`deck.md` §6).
헤드리스(`claude -p`)에서는 Figma MCP가 붙지 않는다. P6-시안 이후는 사람이 앉은 세션에서 한다.
HTML 1장이 필요하면 `python3 scripts/render_html.py 04_제안서_vN.md 06_제안서.html "제목" --md-link 04_제안서_vN.md` — 회사 토큰이 자동으로 들어가고, 공개 금지 정보가 있으면 렌더가 거부된다(`guardrails.md`).
Figma에 들어간 뒤로는 Figma가 정본이다. 슬라이드 덱은 PART(행) 단위로 쪼개 진행한다. 회사 일반현황·조직·실적 장은 `../../templates/company-intro/` 마스터 v3의 구조와 「PROOF — 근거 한 줄」 표기를 참고한다.

### 스텝 종료 시 항상 (루프형)
`_STATE.md` 갱신(현재단계·다음행동·진행중:false·마지막갱신) → `logs/`에 1~5줄 → 사용자에게 3줄 보고 [완료한 것] [다음 스텝] [사람이 처리할 차단사항] → 종료.
스텝 진입 전 끝까지 갈 수 있을지 본다. 어렵다면 시작하지 말고 재개 지점만 더 잘게 적고 종료한다. **반쯤 쓴 문서가 가장 비싼 실패다.**

## 원칙 (반드시 준수)
1. **단일 출처**: 회사명·대표·실적·인증·신용등급·업종코드·숫자는 재료 팩에서만. 임의 입력·추정·기억 인용 금지.
2. **근거 없는 문장은 쓰지 않는다**: `⚠️ 확인필요 — <무엇이 필요한지>`로 남긴다. 조용히 빈칸을 메우지 않는다.
3. **숫자·고유명사를 새로 만들지 않는다**: 재료 팩과 공고 원문에 있는 것만.
4. **게이트는 문서로 증명해야 통과**: 느낌으로 통과시키지 않는다.
5. **공개 금지 정보**(서버 주소·포트·모델명·채널 ID·내부 경로·토큰·임직원 실명)는 산출물에 넣지 않는다. 실명은 사람이 본다.
6. **방향 동의 후 진행**: P3.5 방향은 사용자 확인을 받고 전략으로 간다.
