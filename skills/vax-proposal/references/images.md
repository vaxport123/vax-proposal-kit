# 이미지 — 웹에서 찾아 넣되, 출처 없는 그림은 넣지 않는다

한준 2026-09-04: "필요한 건 웹 크롤링 통한 이미지 넣기" · 2026-08-08: "이미지도 웹에서 찾아서 넣거나 …" · 2026-08-09: "이미지는 보다 놀랍게 화려하게 적극적으로".

글과 도식만 있는 덱은 발주처가 자기 얘기라고 느끼지 못한다. **발주처의 장소·사람·물건이 사진으로 보여야** "이 회사는 우리를 봤다"가 된다.
반대로 어디서 왔는지 모르는 그림 한 장이 제안서 전체를 위험하게 한다(제약-002 같은 저작권 조항은 거의 모든 RFP에 있다). 그래서 **찾는 것은 적극적으로, 넣는 것은 출처가 적힌 것만.**

## 1. 무엇을 찾나 — P3.5 웹 조사와 함께 목록을 만든다
| 종류 | 어디서 | 쓰는 자리 |
|---|---|---|
| 발주처 CI(심벌·로고타입·시그니처) | 기관 「CI 안내」 페이지(공개 다운로드) | 헤더 우상단 전 장 · 표지 |
| 발주처 장소·시설 사진 (캠퍼스·건물·실습실·전시장) | 기관 홈페이지 시설 안내 · 기관 보도자료 · 지자체 공보 · 뉴스 기사(기관 제공 사진) | 문제 인식(hero) · 제안개요 · 공간 관련 절 |
| 발주처 사업 맥락 (기관 행사·수업·클러스터·지역) | 기관 SNS 공개 게시물 · 뉴스 | 배경·pain point 슬라이드 |
| 납품 장비 제품 사진 | **제조사 공식 제품 페이지**(Meta·보관함 제조사) | 장비 규격표 옆 · 운영 시나리오 |
| 우리 실적 사진 | `assets/photos/`(회사소개서 추출 81장, MANIFEST에 사업 캡션) — 웹에서 찾지 않는다 | 차별점·레퍼런스 · 조직 |
| 참고 사례(타 대학 VR 투어 등) | 공개 서비스 화면 | 비교 슬라이드 — **캡처 대신 이름과 링크만** 적는 것이 안전하다 |

찍어야 할 사진(우리가 실측·촬영할 곳)은 그림이 없으면 **빈 사진 카드를 두지 말고** 지도·도식(`layout`)으로 대신한다.

## 2. 사용권 판단 — 이 순서로, 한 줄로 적는다
1. **발주처 자료**(기관 홈페이지·보도자료·CI 페이지) → 발주처에 내는 제안서에 쓰는 것은 통상 문제없다. 「발주처 공식 홈페이지 보도자료」라고 적는다.
2. **제조사 제품 사진** → 그 제품을 납품 제안하는 문서에 쓰는 것은 통상 허용된다. 「제조사 공식 제품 페이지」.
3. **공공누리·CC 라이선스** 표시가 있는 것 → 유형(제1유형·CC BY 등)을 적고, 요구하는 출처 표기를 슬라이드 캡션에 넣는다.
4. **뉴스 사진** → 기관이 제공한 사진(캡션에 「○○대 제공」)만. 언론사 촬영 사진은 쓰지 않는다.
5. **개인 얼굴이 크게 나온 사진·학생 사진** → 쓰지 않는다(초상권). 발주처가 공개한 행사 사진도 얼굴이 식별되면 피한다.
6. **스톡·워터마크·출처 불명·검색 결과 썸네일** → 쓰지 않는다.
7. **생성 이미지**(분위기용 배경) → 표지·PART 구분 배경에만. 실적·현장·장비처럼 **사실을 지는 자리**에는 절대 쓰지 않는다 — 우리가 만든 것처럼 보이면 없는 실적을 적는 것과 같다(서버 `proposal_images.py` 규칙과 같다). 생성한 것은 MANIFEST 사용권 칸에 「생성 이미지(분위기용)」라고 적는다.

판단이 안 서면 넣지 않고 `⚠️ 확인필요 — <어느 슬라이드에 어떤 사진이 필요한지>`로 남긴다. 발표 뒤 폐기되는 자료라도 제안서는 발주처 손에 남는다.

## 3. 절차 (P6 앞에서 · 30분)
1. **목록**: 슬라이드 계획(`07_슬라이드계획_v{N}.md`)의 「사진」 열을 채운다 — 어느 장에 무엇이 필요한지. 보통 6~12장이면 충분하다(전 장에 사진을 깔지 않는다 — 사진이 있는 장이 눈에 띄려면 없는 장이 있어야 한다).
2. **찾기**: Claude가 `WebSearch`(기관명 + 시설명 / 제품명 + 공식) → `WebFetch`로 페이지를 열어 이미지 URL과 캡션·저작권 표기를 확인한다. 검색 결과 썸네일 URL은 쓰지 않는다 — 반드시 원 페이지에서 원본 URL을 딴다.
3. **받기**: `python3 scripts/img_fetch.py bids/<사업> <URL> --name <이름> --use "<슬라이드>" --page <출처 페이지> --license "<판단 한 줄>"`.
   짧은 변 600px 미만·HTML 응답·사용권 빈칸은 거부된다. 1920보다 크면 줄여 저장한다. 같은 URL은 다시 받지 않는다. `bids/<사업>/img/MANIFEST.md`에 한 줄이 쌓인다.
4. **넣기**: Figma에서는 빈 사각형을 만들고 `upload_assets(nodeIds, scaleMode FILL)`로 채운다(`figma-howto.md` 시그니처와 같은 방법). HTML에는 `![캡션](img/파일)`.
5. **캡션**: 사진 아래 12~13px 회색으로 출처를 적는다(「사진: 예시대학교 제공」). 공공누리·CC는 요구 표기 그대로.
6. **검사**: 덱에 들어간 사진이 전부 MANIFEST에 있나(`proposal-critic` B8). 없는 것은 뺀다.

## 4. 하지 않는 것
- 검색 결과 페이지나 이미지 검색 썸네일을 통째로 긁지 않는다. 한 장씩 원 페이지에서 확인한다.
- 경쟁사 자료·타 업체 제안서 이미지를 쓰지 않는다.
- 발주처 CI를 변형(색 바꾸기·기울이기·잘라내기)하지 않는다. CI 안내의 사용 규정을 따른다.
- `img/`는 git에 넣지 않는다(`bids/`는 `.gitignore`). 출처가 적힌 MANIFEST가 있으면 다시 받을 수 있다.
