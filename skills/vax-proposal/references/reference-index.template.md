# 레퍼런스 색인 — 구조 템플릿 (P3가 쓰는 「실적 ↔ 기술요소 ↔ 재활용 문구」 색인)

> **이 파일에는 데이터가 없다.** 실제 실적·인력·금액은 재료 팩 §5(우리 자격·실적·인증)·§7(유사 과거 입찰)로
> 서버가 위키에서 채워 준다. 여기는 그 색인이 **어떤 모양이어야 하는지**만 정한다.
> 왜 데이터를 여기 두지 않나: 이 스킬 폴더는 직원 PC마다 복사된다. 실명·재무·신용등급이 그렇게 퍼지면 안 되고,
> 정본(회사 팩트 DB)과 사본이 조용히 어긋난다(이 저장소에서 반복해 겪은 실패 유형).

## 사용 규칙 (P3)
- P3는 **색인만 읽는다.** 회사 소개 전문을 다시 읽지 않는다 — 색인이 그 역할이다. 색인에 없는 실적이 필요할 때만 원본을 부분 조회한다.
- 군집(A, B, C…)은 **기술요소**로 묶는다. RFP 과업을 기술요소로 분해한 뒤 군집과 짝짓는다.
- 각 군집의 「재활용 문구」는 **그대로 제안서에 쓸 수 있는 문장**이다. 누적 금액·연차가 들어가므로 사업이 끝나면 갱신한다.
- **약점(공백)을 반드시 함께 보고한다.** 잘하는 것만 골라 내면 P5 심사에서 「질 수 있는 지점」이 빠진다.

## 군집 서식

```
## A. <기술요소 군집 이름>   (예: 볼류메트릭 캡처 · 무형유산 기록화)

| 사업 | 발주기관 | 사업비 | 기간 | 역할 |
|---|---|---|---|---|
| (사업명 — 계약서 표기 그대로) | (발주기관 · 원청이 따로 있으면 괄호) | (억 단위 소수 둘째) | YYYY.MM~MM | 주수행 / 제작 / R&D / 공동연구 … |

**보유 인프라·자산** (있으면): 장비 · 스튜디오 · 특허번호 · 파트너 자격
**재활용 문구**
> (2~3문장. 누적 금액·연차·검증 횟수처럼 **수치가 들어간** 사실 문장. 수식어 없이.)
```

## 인력 카드 서식 (투입인력표용)

```
## I. 인력 카드
| 역할 카드 | 핵심 이력 (과업 적합성이 드러나게) | 전담 가능 여부 |
|---|---|---|
```
실명은 재료 팩에서 온다. 제안서에 실명을 넣을지는 발주처 제출 규격을 보고 사람이 정한다(`guardrails.md` §2).
**겸직 노출 주의**: 소수 인력이 여러 역할에 겹치면 전담성이 의심받아 감점된다(`review-rubric.md` §5).

## 레퍼런스 공백 서식 (P3에서 반드시 함께 보고)

```
## J. ⚠ 레퍼런스 공백
| 공백 | 영향(어느 과업·배점에서 감점되나) | 대응 방향(대체 근거 · 컨소시엄 · 발주기관 질의 · 참여 불가 판정) |
|---|---|---|
```
「참여 불가」로 판정되는 공백(예: 법정 자격 미보유)은 P2 게이트에서 즉시 중단 사유가 된다.

## 갱신 규칙
- 신규 계약 체결 → 해당 군집에 한 줄 추가(위키 정본에서). 사업 종료 → 재활용 문구의 누적 금액·연차 갱신.
- 기준일을 맨 위에 적는다. 기준일이 6개월 넘게 지난 색인은 P3에서 「⚠️ 확인필요 — 색인 갱신」으로 표시한다.
