# 재료 팩 계약 — 서버가 쓰고 스킬이 읽는 문서의 고정 목차

서버(`server/proposal_material.py`)가 「도전」 공고마다 위키의 그 공고 페이지 밑에
**「📦 제안 재료 팩 — <공고번호>」** 페이지로 쓴다. 스킬은 이 목차를 그대로 기대한다.
**한쪽만 바꾸지 않는다** — 항목을 더하거나 이름을 바꾸면 이 파일과 서버 스크립트를 함께 고친다.

정량 지표와 회사 자료만 담는다. **전략·컨셉·서술 문장은 넣지 않는다** — 그건 스킬(사람+Claude)의 몫이다.
서버 스크립트는 LLM을 부르지 않는다 — 있는 데이터를 이 틀에 맞춰 모으기만 한다.

## 머리 (H2 앞)
```
# 📦 제안 재료 팩 — <공고번호>
판본: <공고번호>#<제안요청서 도장>#<읽기버전>#<스크립트 버전>     ← 첫 문단. 같은 판본이면 서버가 다시 쓰지 않는다
공고 「…」의 제안 재료. … 열쇳말(기계 추출 · 강한 것): …           ← 실적·군집을 고른 기준 낱말
```

## 목차 (H2 열 개 · 0~9 · 이름 고정)

```
## 0. 공고 기본
공고번호 · 공고명 · 발주처 · 사업 유형 · 추정가격/예산 · 입찰마감 · 제안서 제출 마감 · 우리담당 · 진행상태(도전) · 원문 링크

## 1. 과업 요구 (RFP 추출)
발주처가 시키는 일. 항목별로 원문 근거 위치(쪽·절)를 단다. 요약하지 않고 목록으로.

## 2. 평가배점표
평가항목 | 배점 | 세부기준 | 근거 | 구분(「세부」= 원문에 배점한도·소항목 표현이 있는 것, 기계 판정).
기술 : 가격 비율 · 배점 합계(상위 항목 / 세부 포함). 정성·정량 구분은 스킬 P1에서 사람이 한다.

## 3. 발주처 지정 목차·분량
발주처가 정한 제안서 목차, 절별 분량 제한, 제출 형식(hwp/pdf/pptx 등), 부속 서류.

## 4. 참가자격·필수 서류
참가자격 조건 · 무효 사유 · 제출 서류 목록. 우리 보유 여부를 옆에 표시(보유/미보유/확인필요).

## 5. 우리 자격·실적·인증 (이 공고용으로 고른 것)
하위 절(H3) 다섯 개로 고정:
  5-① 회사 팩트(정본 그대로 · 항목/값/비고)  5-② 인증·자격·특허(인증·입찰자격·직생 전부 + 열쇳말이 닿는 특허, 만료·임박 ⚠️)
  5-③ 유사 실적 후보(프로젝트 DB · 강한 열쇳말이 겹치는 것 · 대외인용금지 제외 · 「겹친 낱말」 열 = 기계 판정)
  5-④ 레퍼런스 색인 군집(위키 「레퍼런스 색인」(01.WIKI_AI / Company)에서 열쇳말 겹침 상위 3개 · 표 + 재활용 문구)
  5-⑤ 인력 카드(색인 §I · 기준일 표시 · 최신 인력구성 문서와 대조할 것)
각 줄에 출처(DB·문서)와 최신 갱신일. 만료 임박(90일 내)은 ⚠️ 표시. 「왜 유사한가」의 논증은 스킬 P3의 몫이다.

## 6. 정량 지표
go/no-go 판정과 점수 · 채점(bid_grade/bid_score) 결과 · 시장·낙찰가 참고(bid_market/bidprc) · 경쟁 밀도.
숫자만, 해석 없이.

## 7. 유사 과거 입찰
공고번호 · 결과(낙찰/유찰/미참여) · 우리 점수 · 배운 것(bid_learn 한 줄). 3~7건.

## 8. 메꿔야 할 빈칸
5·6에서 드러난 부족: 없는 실적, 미보유 인증, 확인 안 된 수치. **스킬이 ⚠️ 확인필요로 옮길 목록**이다.

## 9. 부속 파일
추출된 RFP 원문(마크다운) 링크 · 관련 서식 manifest(별지2호 일반현황·별지7호 실적 등) · 재료 팩 생성 시각·생성 스크립트 버전
```

## 스킬이 읽는 법
- 공고번호로 Notion 검색 → 입찰레이더 행 → 자식 페이지 중 제목이 `📦 제안 재료 팩`으로 시작하는 것.
- H2 열 개(0~9)가 다 있는지 먼저 확인한다. 빠진 것은 사용자에게 알리고 `⚠️ 확인필요`로 다룬다.
- 첫 문단 「판본:」의 도장이 스킬이 전에 읽은 것과 다르면 제안요청서가 바뀐 것이다 — P1부터 다시 본다.
- 8번은 그대로 초안의 확인필요 목록으로 옮긴다. §6은 판단용이라 제안서 본문에 그대로 옮기지 않는다.

## 서버가 쓰는 법 (요지 — 상세는 server/README.md)
- 트리거: 입찰레이더 `진행상태=도전` + 우리담당 지정 + 입찰마감 전(마감일이 없으면 통과). 이미 팩이 있고 판본 도장이 같으면 다시 쓰지 않는다.
- 출처: RFP 읽기 캐시 · 자격 캐시(go/no-go 추출) · 제안요청서 수집(bid_doc_ingest) · 레이더 속성(판정·등급·GoNoGo 4신호) ·
  Notion 덤프(회사 팩트·Certifications·Projects·입찰결과 아카이브) · 개찰·학습 DB(bid_market·bid_learn) · 위키 레퍼런스 색인(Notion API).
- 쓰기 전 공개 금지 검사(서버 주소·포트·모델명·채널 ID·서버 경로·토큰)를 통과해야 쓴다. 통과하지 못하면 쓰지 않고 사유를 찍는다.
- 판본이 바뀌어 다시 쓸 때는 옛 팩을 보관(archived) 처리하고 새 페이지를 만든다 — 사람이 옛 팩에 적은 것은 Notion 휴지통에서 되살릴 수 있다.
