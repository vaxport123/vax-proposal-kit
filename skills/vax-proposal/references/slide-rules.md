# 슬라이드 규칙 — RFP가 정한 것을 먼저, 그 다음 우리 문법

한준 2026-09-04 (순천캠퍼스 VR 덱 24장을 보고):
"제안서 목차에는 페이지 번호를 넣지 마" · "RFP 참고해서 빠지는 사항 없이 모든 걸 넣도록" · "RFP 작성 분량이 있다면 그 분량과 작성 기준을 맞춰" ·
"분량이 없다면 예산과 과업 내용을 참고해서 장표 수를 짜" · "작성 규칙은 RFP 참고. 목차 규칙이 있으면 무조건 따라야" ·
"헤더라고 칭할 부분은 목차/구분 로고를 헤더처럼 넣어 정렬 맞춰서" · "항상 쪽번호" · "타이틀은 그 장표의 모든 근거를 담은 하나의 주장이어야 하고 다음 장표 타이틀과 이어져야" · "본문 다 넣어".

`figma-handoff.md`는 **생김새**(색·글꼴·유형)를, 이 문서는 **구성 규칙**(무엇을 몇 장에 어떤 순서로, RFP를 어떻게 따르나)을 맡는다.

## 1. RFP에서 먼저 뽑는 것 (P1에서 `01_평가표.md` §7에 적는다)
RFP 「제안서 작성 요령·목차·제출 규격」 절을 찾아 아래 표를 채운다. **없으면 `[RFP에 명시 없음]`** — 추측으로 채우지 않는다.
| 항목 | 예(순천캠퍼스 VR) | 우리가 하는 것 |
|---|---|---|
| 지정 목차 | Ⅰ 제안개요(3절) · Ⅱ 사업수행(3절) · Ⅲ 사업관리(3절) · Ⅳ 사업지원(2절) · Ⅴ 기타 | **글자 하나 바꾸지 않고 그대로.** 절 순서·이름·번호 유지. 우리가 넣고 싶은 것은 그 절 안에서 소제목으로 |
| 분량 제한 | 정량 평가서 표지·목차 포함 20쪽 · 정성 제안서 `[명시 없음]` | 제한이 있으면 그 쪽수가 상한이고 표지·목차 포함 여부까지 그대로. 없으면 §2로 장수를 정한다 |
| 용지·방향 | A4 세로 원칙, 부득이하면 가로 일부 | 슬라이드 덱(1920×1080)은 「가로 일부」에 해당한다. 발표용 덱과 제출용 제안서가 같은 문서라면 인쇄 시 A4 가로. 세로 강제면 덱이 아니라 문서로 낸다 |
| 쪽번호 규칙 | 하단 중앙 · **장별로 번호 부여** | 「Ⅱ-3」처럼 장 로마숫자 + 장 안 일련번호. 통번호(1, 2, 3…)로 하지 않는다. 표지에는 없고 목차부터 |
| 문체·용어 | 한글 · 영문 약어에 약어표 · 「~할 수도 있다 / ~이 가능하다 / ~을 고려하고 있다」는 불가능으로 간주 | 약어표 슬라이드 1장(목차 다음) · 금지 표현은 `proposal-critic`이 Grep으로 센다 |
| 빈 항목 처리 | 「해당 내용이 없을 경우 "해당사항 없음"으로 기재」 | 지정 목차의 절을 비워 두지 않는다. 없으면 「해당사항 없음」과 이유 한 줄 |
| 특화사항 | 「부분별로 제안업체만의 특화사항이 있을 경우 별도 기술 가능」 | Ⅴ 기타·추가 제안에 모은다. 값을 올리지 않는 것만 |
| 참고문헌 | 「참고문헌 활용 시 목록 첨부·인용 부분 명시」 | 웹 조사 출처(`03b_방향전략.md` §0)를 마지막 장 「참고문헌」에 목록으로 · 본문 인용 자리에 [1] 번호 |
| 별지 | 「기술 설명 자료가 많으면 별지 사용」 | 장비 상세 규격·인력표·실적표는 본문에 요약 + 별지 표 |
| 발표 | 10분 발표 + 10분 질의 · 발표 내용 = 제안서 내용 | 제목 사슬(§3)을 순서대로 읽는 시간이 10분 안이어야 한다(장당 12~15초 → 40~50장) |

## 2. 장수 — 제한이 없을 때 이렇게 정한다
장수는 「보여 줄 내용의 양」에서 나온다. 예산·과업 개수·정성 세부 항목 수를 함께 본다.
```
본문 장수 ≈ (정성 세부 평가항목 수 × 2) + (RFP 요구사항 ID 수 × 0.7) + (장비·산출물 표 수)
전체     = 표지 1 + 목차 1 + 약어표 0~1 + PART 구분(장 수) + 본문 + 마무리 1 + 참고문헌 0~1
```
| 예산·규모 | 대략 | 근거 |
|---|---|---|
| 1억 미만 · 과업 20개 안 · 정성 10항목 안 | **40~48장** | 순천캠퍼스 VR: 세부 10항목×2 + 요구 ID 12×0.7 + 표 6 ≈ 34 본문 + 뼈대 10 = 44 |
| 1~3억 · 과업 20~40 | 48~60장 | 실측 3덱(재도전·생명지킴이·공정자동화) 44~54장 |
| 3억 이상 · 다년 · 다기관 | 60~80장 | 절마다 별지 표가 늘어난다 |
장수를 채우기 위해 내용을 늘리지 않고, 줄이기 위해 내용을 빼지 않는다. 계산이 나온 뒤 **초안 문단을 전부 배치했는데 남는 문단이 있으면 장을 늘린다**(§4).
발표 10분 상한을 넘으면(장당 15초 × 장수 > 600초) 발표에서 건너뛸 장(별지 표)을 발표자 노트에 표시한다 — 장을 빼지 않는다.

## 3. 제목 사슬 — 제목만 읽어도 발표가 된다
- **본문 슬라이드 제목은 한 문장 주장**이다. 그 장의 도식·표·수치가 전부 그 주장의 근거여야 한다. 근거가 제목을 못 받치면 제목이 틀렸거나 장을 나눠야 한다.
  「사업 개요」「추진 전략」같은 명사 제목은 PART 구분 슬라이드에만.
- **다음 장 제목과 이어져야 한다.** 슬라이드 계획을 쓸 때 제목만 한 줄씩 모아 위에서 아래로 읽는다. 「그래서 → 그런데 → 그러려면 → 그 결과」로 읽히면 된다. 끊기는 곳은 장 순서를 바꾸거나 제목을 고친다.
  예(Ⅰ 제안개요): "순천캠퍼스에는 아직 보여 줄 캠퍼스가 없습니다" → "그래서 5분 안에 걸어 보게 하고, 원도심 전체가 캠퍼스임을 보여 줍니다" → "그러려면 실측 공간·캐릭터 안내자·한 사람이 돌리는 15대, 세 가지가 필요합니다" → "이 셋은 저희가 이미 해 본 일입니다".
- 제목 48~50px · 강조 낱말 1~2개(발주처 CI 색) · 40자 안(한 줄에 약 37자, 두 줄까지). 40자를 넘으면 부제(20~24px 회색)로 근거 한 줄을 내린다.
- **결론 바**는 제목을 되풀이하지 않는다. 제목이 「우리가 무엇을 한다」면 결론 바는 「그래서 발주처에 무엇이 좋다」.
- 제목 사슬은 `07_슬라이드계획_v{N}.md` 맨 위에 목록으로 먼저 쓴다. 이것이 10분 발표 원고의 뼈대다. `proposal-critic` B2·B3이 이 목록을 본다.

## 4. 본문 전체 수록 — 요약하지 않는다
한준 2026-09-04 "본문 다 넣어". 24장 덱이 26,000자 초안을 요점만 뽑아 담았던 것이 문제였다.
- **초안의 모든 문단이 덱 어딘가에 있어야 한다.** 문단 하나는 ① 도식·표의 데이터가 되거나(`figures.md`) ② 도식 옆 본문 텍스트 블록(18~20px, 3~6줄)이 되거나 ③ 결론 바가 된다. 셋 중 어디에도 못 넣은 문단은 장을 하나 더 만든다.
- 절 하나가 길면 유형이 바뀌는 곳에서 자른다(문제 → 표 → 사례처럼). 한 절이 2~4장이 된다.
- 문장을 줄여 넣지 않는다. 슬라이드 폭에 안 들어가면 텍스트 블록을 둘로 나누거나 글자 크기를 18까지 내린다(그 아래로 내리지 않는다). 그래도 안 되면 장을 나눈다.
- 「요점」 불릿은 덱에 넣지 않는다 — 그 내용은 이미 제목·결론 바·도식이 맡았다. 발표자 노트에는 넣는다.
- 검사: 슬라이드 계획의 각 장에 「초안 문단 번호」 열을 두고, 초안 문단을 전부 세어 빠진 번호가 없는지 본다(`proposal-critic` B9).

## 5. 헤더·쪽번호 — 전 장 같은 좌표
- **헤더(상단 띠)**: 좌상단 브레드크럼 「Ⅱ. 사업수행 부문 › 3. 장비 납품」(장 굵게·절 흐리게, 20~22px) · 우상단 발주처 시그니처(PNG, 높이 44~52) · 그 아래 1px 실선 전폭. 좌표는 전 장 동일(예: 브레드크럼 x=96 y=48 · 시그니처 우측 끝 x=1824 · 실선 y=112). PART 구분·표지에는 시그니처만.
- **쪽번호**: 하단 중앙, 15px, 회색, **장별 번호** 「Ⅱ-3」. 표지에는 없다. 목차·약어표는 번호 없이 두거나 RFP가 정한 대로(RFP가 "표지와 목차 포함"이라 하면 목차부터 1).
- **목차 슬라이드에는 쪽번호를 적지 않는다.** 장 로마숫자·장 제목·절 제목만(강조색은 로마숫자). 이유: 덱이 바뀔 때마다 목차 숫자가 어긋나고, 심사위원은 목차의 쪽수를 쓰지 않는다.
- 발주처 시그니처는 텍스트 자리표시가 아니라 실제 PNG(`figma-handoff.md` §6). 헤더 아래 본문 영역은 y=140~960, 결론 바 y=960~1020, 쪽번호 y=1040.

## 6. RFP 누락 검사 — 요구사항 ID 전부에 슬라이드 번호가 붙어야 한다
- RFP의 요구사항 목록(기획-001 … 제약-002처럼 ID가 있으면 ID로, 없으면 과업 문장을 번호 매겨)을 `07_슬라이드계획_v{N}.md` 끝에 표로 두고 **대응 슬라이드 번호**를 채운다. 빈 칸이 있으면 장을 추가하거나 「해당사항 없음」을 명시한 장에 넣는다.
- 요구사항 상세설명의 **하위 항목(동그라미·붙임표 불릿)까지** 센다. 예: 기능-002의 「대학 역사·연혁」과 「학과 커리큘럼·졸업 후 진로」는 콘텐츠 시나리오에 장면이 있어야 한다. 장비 목록의 품목은 **전부** 규격표에 있어야 한다(순천 덱 v1은 9품목 중 5품목만 있었다).
- 산출물(보고서 3종·매뉴얼·원본 파일)과 계약 조건(보안 서류·지식재산권·하자보수 기간·타 기관 공동활용)도 각각 대응 슬라이드가 있어야 한다.
- 이 표는 P5 심사와 `proposal-critic` B9가 함께 본다.

## 7. 순서 (P6에서)
1. `01_평가표.md` §7에서 RFP 규칙(§1 표)을 읽는다. 2. §2로 장수를 잡는다. 3. 제목 사슬을 먼저 쓴다(§3). 4. 초안 문단을 장에 배치하고 도식 유형·사진·초안 문단 번호를 적는다(§4·`figures.md`·`images.md`). 5. RFP 요구 ID 대응표를 채운다(§6). 6. `proposal-critic`(mode deck)로 검토 → 고친 뒤 Figma에 만든다(`figma-handoff.md` §6). 7. 만든 뒤 덱 텍스트를 뽑아 내부 표기(근거·확인필요)가 남았는지 검색한다.
