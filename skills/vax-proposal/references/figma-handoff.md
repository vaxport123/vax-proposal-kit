# Figma 핸드오프 — HTML 디자인을 Figma에 넣고 Claude-Figma로 다듬기

렌더한 HTML은 **초안**이다. Figma에 들어간 순간부터 Figma가 정본이고, 세부 디자인은
Claude-Figma(Figma MCP)로 조정한다. HTML을 다시 렌더해 Figma 위를 덮어쓰지 않는다.

## 전제
- Figma 공식 MCP 커넥터가 Claude에 연결돼 있어야 한다.
- Figma를 부르기 전에 **반드시** `/figma-use` 스킬(또는 `skill://figma/figma-use/SKILL.md`)을 먼저 읽는다 — Figma MCP 규칙이다.

## 절차
1. **파일 준비**: 대상 Figma 파일(또는 새 파일)을 정한다. 팀 디자인 라이브러리가 있으면 `get_libraries`로 확인해 그 컴포넌트를 우선 쓴다.
2. **HTML → Figma**: `render_html.py`가 만든 HTML(또는 그 소스)을 Figma 생성 도구로 넣는다.
   페이지 단위 레이아웃이면 `/figma-generate-design` 절차를 따른다. 한 장짜리 제안서는 아트보드 하나로, 슬라이드형이면 절별로 프레임을 나눈다.
3. **토큰 맞추기**: 들어간 뒤 색·모서리·글꼴이 `house-style.md`의 토큰과 같은지 본다. Figma 변수(`get_variable_defs`)에 회사 토큰이 있으면 그것에 연결한다. 없으면 만들지 말고 사용자에게 알린다.
4. **세부 조정은 Claude-Figma로**: 여백·정렬·강조·이미지 배치는 Figma 안에서 `use_figma`로 고친다. 이 단계에서 문장을 고치면 **노션 초안에도 같은 수정을 남긴다**(사본이 어긋나지 않게).
5. **내보내기**: 제출 형식이 pdf면 Figma에서 내보내고, hwp/pptx가 필요하면 하류 스킬(`vax-exit-kit`·`doc-gen`·`claw-hwp`)로 넘긴다.

## 우리가 실제로 한 방식 — 제안 슬라이드 3덱 실측 (한준 2026-09-04 "이때 디자인을 어떻게 했는지 참고")
HTML 초안을 Figma Slides로 옮겨 완성한 덱 세 개(재도전 인식개선·우정종사원 생명지킴이 영상·공정자동화 3D 시각화, 각 44~54장, 1920×1080)를
Figma MCP로 읽어 공통 문법을 뽑았다. **새 덱은 이 문법을 기본으로 삼고, 발주처와 과업에 따라 색과 소재만 바꾼다.**

### 1. 색 — 발주처 CI 강조색 하나 + 중립 회색 단계. 백스포트 색은 쓰지 않는다
| 덱 | 발주처 | 강조색 | 진한 글자·바 | 흐린 글자 | 옅은 면 | 보조 강조 |
|---|---|---|---|---|---|---|
| 재도전 인식개선 | 한국청년기업가정신재단 | 파랑 `#1b4fc4` | 남색 `#0b2148` | 회청 `#3a4661` | `#e6edf8` `#eceef2` | 노랑 `#ffcc00`(어두운 면 위 숫자) |
| 생명지킴이 영상 | 한국자살예방협회 | 빨강 `#e8202a` | 검정 `#141414` | `#4c4c4c` `#949494` | `#e4e4e4` `#f7f8f9` | 없음(빨강 하나) |
| 공정자동화 3D | KITECH | 파랑 `#0047bb` | 남색 `#002b73` `#0e141d` | `#68727f` `#96a0ac` | `#fafbfd` `#d3dae3` | 노랑 `#ffb814`(카드 3번째·선정 기준) |

- 강조색은 **발주처 로고 색**에서 가져온다. 제안서의 주인공은 발주처다. 우리 브랜드 남색(`#082567`)은 표지 회사명에도 쓰지 않았다.
- 강조색이 쓰이는 자리는 정해져 있다: 제목 문장 안의 낱말 1~2개, 카드 번호(01·02·03), 카드 상단 가는 띠, 표 첫 열 번호, 결론 바의 낱말. 면 전체를 강조색으로 칠하는 건 결론 바·표 머리 행만.
- 나머지는 전부 무채색 단계(진한 글자 → 본문 회색 → 캡션 회색 → 옅은 면 → 흰 바탕). `house-style.md`의 무채색 원칙과 같다.
- **HTML 초안 → Figma 갈 때 색을 이렇게 바꾼다**: HTML은 회사 토큰(사내 문서용)으로 렌더되고, Figma에서 강조색만 발주처 CI로 치환한다. 그래서 `render_html.py`가 `var(--brand)` 한 변수만 강조에 쓰는 것이 중요하다 — 치환 지점이 하나다.

### 2. 글꼴 — Freesentation 한 가족, 굵기로만 단계를 만든다
- 제목·라벨·표 머리 = **Freesentation 7 Bold**(전체 텍스트의 60~70%) · 본문 = **4 Regular** 또는 **5 Medium** · 브레드크럼·쪽번호 = **3 Light** · 큰 숫자·PART 번호 = **9 Black**.
- 재도전 덱만 Noto Sans KR을 보조로 섞었다(로고 주변). 새 덱은 Freesentation 하나로 간다. Figma에 글꼴이 없으면 사용자에게 알린다(대체하지 않는다).
- 크기 단계(1920 기준): 브레드크럼 20~25 · **제목 문장 48~50** · 부제 20~24 · 카드 제목 25~30 · 본문 18~23 · 표 16~28 · 쪽번호 15 · 구분 슬라이드 제목 76~126 · 배경 큰 숫자 360~520 · 표지 제목 68~100.

### 3. 슬라이드 한 장의 해부 (본문 슬라이드 — 전체의 80%)
```
┌ 좌상단: 「Ⅱ. 제안업체 소개  2. 조직 및 인원」 브레드크럼(장 굵게 · 절 흐리게)      우상단: 발주처 로고 ┐
│ 소제목 라벨(강조색, 20px, 앞에 세로 막대 또는 밑줄): 「조직 구성」                                     │
│ 제목 문장(48~50 Bold, 한 문장, 주장형 "~합니다", 낱말 1~2개 강조색): 「본 사업 전담 수행조직 13인을 …」 │
│ 부제(20~24 회색): 제목을 뒷받침하는 사실 한 줄                                                       │
│                                                                                                     │
│ 본문 = 카드 3열 / 표 / 좌 도식·우 표 / 사진 카드 4열 중 하나                                          │
│                                                                                                     │
│ 하단 결론 바(전폭, 옅은 강조면 또는 진한 남색면 + 강조 낱말): 「지원 성과를 제대로 보여주려면 … 연결」  │
└ 하단 중앙 쪽번호(15px)                                                                              ┘
```
- **제목은 늘 주장 문장이다.** 「사업 개요」 같은 명사 제목은 구분 슬라이드에만 쓴다. 제목 한 줄만 읽어도 그 장의 결론을 알게 한다(`distinctiveness.md` 규칙 6·7과 같은 논리).
- **결론 바**가 있는 장이 많다. 심사위원이 본문을 건너뛰어도 마지막 줄에서 결론을 집게 한다.
- 밀도가 높다(장당 도형 50~130개). HTML 초안의 표·목록을 줄이지 않고 그대로 카드·표로 옮겼다는 뜻이다.

### 4. 반복되는 슬라이드 유형 (HTML 초안의 절 → 이 유형으로 옮긴다)
| 유형 | 언제 | 생김새 |
|---|---|---|
| 표지 | 1장 | 흰 바탕 또는 진한 바탕. 사업명(68~100 Black/Bold) + 한 줄 캐치프레이즈(46) + 회사명·제출일(21~24). 재도전 덱은 2장에 「원본 증명」 슬라이드를 따로 둠(발주처 서식 요구) |
| 목차 | 1장 | 「제안 목차」 + 장별 로마숫자·쪽 범위(P.03~09)를 강조색으로, 절 목록은 회색 |
| PART 구분 | 장마다 1장 | 옅은 회색 바탕에 **거대한 장 번호(360~520px)를 배경색보다 조금 진한 색으로**, 왼쪽에 강조색 세로선 + PART 라벨 + 장 제목 + 한 줄 설명. 재도전 덱은 남색 그라데이션 어두운 배경 |
| 문제 인식(hero) | 제안개요 첫 장 | 어두운 남색 그라데이션 전면, 제목 86px에 **핵심 숫자만 노랑**, 아래 근거 두 줄, 출처는 테두리 알약 버튼 2개 |
| 숫자 대비 | 문제 정의·목표 | 큰 숫자(70~106px) 둘을 「그런데」로 잇고 아래 라벨·출처. 옆에 남색 박스로 「퍼뜨릴 문장 하나」 |
| 카드 3열 | 원인·전략·원칙·목표 | 상단 가는 강조 띠 + 01/02/03 번호 + 카드 제목(25~30) + 본문 2~3줄 + 하단 결론 버튼. 3C 전략처럼 카드마다 색을 다르게 한 사례도 있다(파랑·청록·노랑) |
| 표 | 산출물·요구 대조·인력·인증·실적 | 머리 행은 진한 남색/검정 면에 흰 글자, 첫 열은 강조색 번호(01…), 행 사이 옅은 줄, 5~7열까지 |
| 사진 카드 4열 | 직군·대상·장소 | 사진 위에 어두운 캡션 띠(제목+한 줄) → 아래 「이런 변화가 보입니다 / 장면에서 보여줄 것」 라벨·본문 → 하단 결론 바 |
| 조직·인력 | 제안업체 소개 | 좌: 조직도(대표 박스 → 부문 5개 박스, 부문 색은 남색 머리), 우: 인력표(성명·직위·담당·핵심 경력), 하단 「인력 운영 원칙」 남색 바 |
| 공정·파이프라인 | 제작 방식 | 가로 단계 카드(기획 → 세트 → 촬영 → …) 사이 화살표, 각 카드에 수치(협의 5회·촬영 2일) |
| RFP 대조 | 과업 이해 | 「제안요청서 요구 / 표준·우리 대응 위치 / 판정」 3열 표 — P1 평가표 검산 결과를 그대로 슬라이드로 |

### 5. HTML → Figma 옮길 때의 순서 (세 덱에서 한 방식)
1. HTML 초안의 **장 하나 = PART 구분 슬라이드 하나**, **절 하나 = 본문 슬라이드 1~3장**. 절이 길면 유형(카드/표/사진)이 바뀌는 지점에서 자른다.
2. 절의 첫 문장을 **제목 문장**으로 다듬는다(주장형, 48~50px, 강조 낱말 1~2개). 절의 마지막 문장은 **결론 바**로.
3. 표는 표로, 「①②③」 나열은 카드 3열로, 수치가 주인공이면 숫자 대비형으로.
4. 강조색을 발주처 CI로 치환한다. 노랑 보조색은 어두운 면 위 숫자에만.
5. 발주처 로고를 우상단, 브레드크럼을 좌상단, 쪽번호를 하단 중앙에 — 전 장 동일 위치.
6. 밀도를 줄이지 않는다. 대신 위계(제목 → 부제 → 카드 제목 → 본문 → 캡션)를 크기·굵기·색으로 분명히 한다.

## 하지 않는 것
- Figma에 들어간 디자인을 HTML로 역변환해 다시 정본으로 삼지 않는다.
- **제안 슬라이드의 강조색은 발주처 CI를 따른다(위 §1).** 회사 토큰(`ops/ui_tokens.py`)은 HTML 초안·사내 문서의 정본이고, Figma 덱에서는 강조색 한 자리만 발주처 색으로 바꾼다. 그 밖의 색(무채색 단계)·글꼴·간격은 새로 만들지 않는다.
- 공개 금지 정보(`guardrails.md`)는 Figma 파일에도 넣지 않는다 — Figma 링크는 쉽게 밖으로 나간다.
