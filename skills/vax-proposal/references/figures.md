# 도식·표 우선 — 글 대신 SVG로 보여 준다

한준 2026-09-04: "텍스트 대신에 SVG 기반의 도식화나 표 처리" · 2026-07-30: "도식화나 표 구조 넣고 이미지 찾아 넣고 해서 제대로된 걸로".

심사위원은 한 업체 제안서에 몇 분을 쓴다. 문단은 읽어야 알지만 도식은 보면 안다. 그래서 **비교·대조·순서·수치·일정·체계·구성은 글로 쓰지 않고 그린다.**
글은 도식이 못 담는 것(왜 그렇게 하는가, 발주처가 겪는 문제, 우리 경험)만 맡는다. 내용을 줄이라는 뜻이 아니다 — 같은 내용을 **읽는 형식에서 보는 형식으로** 바꾸는 것이다.

## 1. 한 데이터, 두 목적지
`scripts/figures_svg.py`가 마크다운 초안의 ```fig 블록(JSON 하나)을 SVG로 그린다.
- **HTML 초안**: `render_html.py`가 자동으로 인라인 SVG로 끼운다. 색은 `var(--brand)` 같은 토큰 변수라 회사 토큰·다크모드를 따른다.
- **Figma 덱**: `python3 scripts/figures_svg.py 04_제안서_v5.md --out-dir figs/ --accent "#0068B0"`으로 발주처 CI 색을 박은 `.svg` 파일을 뽑고,
  Figma 플러그인 API `figma.createNodeFromSvg(svg문자열)`로 슬라이드에 올린다. 도형·텍스트가 **편집 가능한 노드**로 들어가므로 Claude-Figma에서 계속 다듬을 수 있다.
  같은 JSON에서 두 결과가 나오므로 문구를 고치면 둘이 같이 바뀐다. 그림 파일(PNG)로 넣으면 안 바뀐다 — 그래서 SVG다.
- 서버 `proposal_figures.py`(HTML/CSS 도식 10종)와 **같은 계약**(`type` + 종류별 필드)이다. 옛 payload를 그대로 붙여도 그려진다.

## 2. 어느 내용을 어느 도식으로 — 초안을 쓰면서 바로 지정한다 (P4)
| 초안에 이런 내용이 나오면 | 이 유형으로 | 필드 |
|---|---|---|
| 요구 ↔ 우리 답 ↔ 근거 (RFP 대조·과업 이해) | `matrix` | `rows:[{req,ans,ev}]` — 근거 비면 ⚠️ 확인필요가 자동으로 박힌다 |
| 규격·품질 기준과 검수 방법 (수치 약속) | `spec` | `rows:[{item,value,how}]` — 값 비면 확인필요 |
| 원인·전략·원칙·차별점처럼 **셋**을 나란히 | `cards` | `items:[{h,b,foot}]` 2~4장 · `foot`은 카드 결론 한 줄 |
| 수치가 주인공 (3층·48곳·282명·60명) | `stats` | `items:[{n,label,src}]` 2~4개 |
| 단계가 왼쪽에서 오른쪽으로 흐름 (제작 공정·파이프라인) | `flow` | `steps:[{h,b}]` ≤6 |
| 순서가 있는 운영 절차 (한 반 운영 5단계) | `steps` | `steps:[{h,b}]` ≤8, 세로 |
| 시스템 구성 요소와 고장 대응 | `system` | `rows:[{h,b,spec,fail}]` |
| 위→아래 층 (시스템 네 덩이·데이터/플랫폼) | `layers` | `layers:[{h,b}]` |
| 조직·추진 체계 | `arch` | `top`, `groups:[{h,items}]` — 인력표는 `table`로 옆에 |
| 주·월 단위 일정 | `gantt` | `units:13, unit:"주", bars:[{h,from,to,out}]` |
| 위험·원인·영향·대응 | `risk` | `rows:[{risk,cause,effect,plan}]` |
| 선정 기준·대상 (선정 배점이 있는 공고) | `select` | `criteria:[{h,b}]`, `rows:[{item,why,grade,note}]` |
| 공간 배치·동선 (도면 없어도) | `layout` | `space`, `zones:[{h,pos,b}]`, `path` — note에 「개념도」라고 적는다 |
| 그 밖의 모든 마크다운 표 | `table` | `head:[…]`, `rows:[[…]]`, `widths:[비율]`, `font` |

초안에 쓰는 법 — 문단 바로 아래에 블록을 둔다(문단은 지우지 않는다. 슬라이드에서는 도식이 본문이 되고 문단은 발표자가 읽는다):
```fig
{"type": "stats", "title": "순천캠퍼스의 진짜 크기", "items": [
  {"n": "3층", "label": "시민공익활동지원센터 강의실·실습실", "src": "한국대학신문 2025-03"},
  {"n": "48곳", "label": "걸어서 5분 안 애니메이션 기업", "src": "AI타임스"},
  {"n": "282명", "label": "클러스터 종사자", "src": "전매일보"},
  {"n": "60명", "label": "2028 유학생 목표", "src": "학과 로드맵"}]}
```
빈 값은 채우지 않는다. `matrix`의 근거, `spec`의 값, `select`의 선정 근거가 비면 렌더러가 `⚠️ 확인필요`를 색 있는 칸으로 박는다 — "고품질" 같은 말로 덮는 것보다 낫다(guardrails §3·§4).

## 3. 검사 (P4 검토 ③ · P6 전)
- 초안의 **마크다운 표는 전부** ```fig(`table` 또는 위 유형)로 옮겼나. `python3 scripts/figures_svg.py 04_제안서_v5.md --list`로 블록 목록을 뽑아 절과 대조한다.
- 숫자가 셋 이상 나오는 문단 옆에 `stats`가 있나. 「첫째·둘째·셋째」 옆에 `cards`가 있나. 「주차·개월」이 나오면 `gantt`가 있나.
- 글만 있는 슬라이드가 연속 두 장 넘게 있으면 도식으로 바꿀 것을 찾는다(`proposal-critic` B5).
- 도식 안 글자는 **15px 이상**(1200 폭 기준 → 슬라이드 1728 폭으로 늘리면 약 22px). 줄이 넘쳐 「…」가 생기면 문구를 줄이지 말고 `widths`·`font`를 조정하거나 표를 두 장으로 나눈다.

## 4. 하지 않는 것
- 도식을 **이미지(PNG)** 로 굽지 않는다. 고칠 수 없고 흐려진다. 사진은 `images.md`, 도식은 SVG.
- 도식 안에 색을 새로 만들지 않는다. 강조색 하나(발주처 CI) + 무채색 단계 — `figures_svg.palette_hex(accent)`가 만든 것만.
- 도식으로 바꾼 뒤 문단을 지우지 않는다. 문단은 제안서(문서)와 발표자 노트에 남고, 슬라이드에는 도식 + 결론 바가 남는다(`slide-rules.md` §4 「본문 전체 수록」).
- 도식 종류를 새로 만들 때는 `figures_svg.py`에 함수 + 셀프테스트 + 이 표에 한 줄을 같이 넣는다. 서버 `proposal_figures.py`와 계약이 갈라지면 서버 쪽도 고친다.
