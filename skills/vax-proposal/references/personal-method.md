# 개인 방식 — 각자의 취향을 공통 규칙 위에 얹는다 (P0 ⓞ · P4)

한준 2026-09-08: "브랜치마다 커스텀을 올리게 하면 깃허브 가입이 또 필요하고, 폴더 없이 채팅에서만 일하는 직원도 있다 — 노션에 방식으로 모으자."
그래서 **사람마다 노션 한 페이지**다. Claude Code 스킬도, 채팅판 Claude도 같은 페이지를 읽는다.

## 어디에 있나
- 데이터베이스: 노션 01.WIKI_AI › Company › **「✍️ 제안 방식 — 개인별 커스텀」** (데이터 소스 `e79e15a0-eb83-44fe-a517-3bf9fa751c62`)
- 속성: 이름(「제안 방식 — 이름」) · 담당자(PEOPLE) · 상태(사용중/초안/보류/안내) · 적용 범위 · 사용 도구 · 한 줄 소개 · 최종수정
- 본문 여섯 절(제목을 바꾸지 않는다): **1. 내 문체 규칙 · 2. 자주 쓰는 방향 문구 · 3. 내가 꼭 보는 검토 항목 · 4. 참고 덱·자료 링크 · 5. 피하는 표현·디자인 · 6. 변경 기록(표)**
- 틀: 「(틀) 제안 방식 — 이름」 행을 복제한다. 안내·프롬프트: 「📌 사용 안내」 행.

## 사용자는 켜고 끄지 않는다 — 키트를 설치하면 알아서 된다 (P0 ⓞ)
한준 2026-09-08: "노션 방식 모을 때 kit 설치하면 알아서 되도록. 뭘 켜고 끄고 하지 않게."
1. `notion-fetch self`로 지금 사용자(이메일)를 확인한다.
2. `notion-query-data-sources`로 담당자 = 그 사용자인 행을 찾는다. 상태는 보지 않는다(「보류」로 직접 바꾼 것만 건너뛴다).
3. **있으면** `notion-fetch`로 본문 여섯 절을 읽고 `_STATE.md`에 `개인방식: {page_id, 읽은 일시, 절 요약 한 줄}`.
4. **없으면 Claude가 만든다** — `notion-create-pages`(데이터 소스 위) 제목 「제안 방식 — {이름}」, 담당자 = 사용자, 상태 = 사용중, 사용 도구 = 지금 쓰는 도구, 본문은 여섯 절 제목만. 사용자에게는 「제안 방식 페이지를 만들었습니다. 작업하며 정하는 규칙은 여기에 자동으로 쌓입니다」 한 줄. 이름을 모르면 이메일 앞부분을 쓰고 사용자가 바꾼다.
5. 두 명 이상 걸리면(중복 페이지) 최근 수정 페이지를 읽고 「페이지가 둘입니다. 하나로 합칠까요」를 P5 통과 시점에 한 번 묻는다.

## 우선순위 — 개인 취향이 넘지 못하는 것
게이트(P2 실점·P5 80점·초안/덱 게이트) · 근거 없는 문장 금지 · 재료 팩 계약 · 공개 금지(기밀·연락처·재무) · RFP 작성 규칙(`deck.md` §1).
개인 페이지가 이 중 하나를 풀라고 하면 따르지 않고, 「공통 규칙이 우선입니다 — 바꾸려면 저장소 PR」 한 줄을 알린다.

## 저장하는 법 — 묻지 않고 쌓는다
작업 중 사용자가 규칙을 정하면(「앞으로 ~하게 써」「이 표현 쓰지 마」「이 덱 참고해」「이건 꼭 확인해」) **묻지 않고** `notion-update-page`로 **해당 절 끝에 덧붙이고** 6절 변경 기록 표에 `날짜 | 어느 공고 | 무엇을` 한 줄을 넣는다. 어느 절인지는 말의 종류로 정한다: 문장 습관 → 1 · 방향 뼈대 → 2 · 확인 항목 → 3 · 링크 → 4 · 금지 → 5. 한 공고에서 여러 번이면 P5 통과 시점에 「이번에 저장한 규칙 n개」로 한 번 알린다. 기존 글을 지우거나 고쳐 쓰지 않는다. 남의 페이지는 만지지 않는다.
회사 사실(실적·인력·재무)은 여기에 적지 않는다 — 그것은 01.WIKI_AI 정본이다.

## 채팅판 Claude(폴더 없음)
노션 커넥터만 붙어 있으면 「📌 사용 안내」의 한 줄 프롬프트로 같은 동작(찾기 → 없으면 만들기 → 얹기 → 쌓기)을 한다. 스킬 없이도 여섯 절을 읽고 얹는 것까지는 된다. 게이트·스크립트(gap_check·readiness·비판자)는 Claude Code에서만 돈다.
