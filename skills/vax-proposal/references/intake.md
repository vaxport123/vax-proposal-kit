# 접수(인테이크) — 키트는 대화로 재료를 다 받은 뒤에만 초안을 쓰고 피그마를 연다

한준 2026-09-06: "키트의 의미처럼 사용자와 상호작용하면서 필요한 자료 요구하고, 모든 자료·아이디어가 완성되었을 때 초안 제작과 피그마 디자인 시작이 이뤄지도록. RFP 넣어 달라 하거나, 주요 방향성 달라 하거나, 피그마 연결·노션 연결 요구하고."

키트는 **묻는 쪽**이다. 사용자가 무엇을 줘야 하는지 스스로 알아야 하는 도구가 아니라, 필요한 것을 순서대로 요구하고 다 갖춰졌는지 기계로 확인한 뒤에 만드는 도구다. 게이트는 둘이다.
- **초안 게이트**(P4 앞): RFP · 노션 연결(또는 재료 팩 직접 제공) · 평가표·가점·레퍼런스 · 페인포인트·색채 카드 · **사용자가 말로 준 방향** · 방향 동의 · 확인필요 0(또는 사용자가 「그대로 진행」이라 답함).
- **덱 게이트**(P6 ⑨ 피그마 앞): 초안 게이트 통과 · 심사 80점 · **피그마 연결**(whoami·라이브러리 열림) · 재료점검 여섯 항목(결정·반대 셋·발주처 사진 6·우리 실물 6·숫자 5·카드 8) · 고스트 덱 승인.
판정은 `scripts/readiness.py bids/<사업> --gate draft|deck`가 한다. 통과 전에는 초안도 피그마도 시작하지 않는다.

## 1. 첫 대화 — 다섯 묶음을 이 순서로 (한 번에 한 묶음)

준비 점검(P-1)이 끝나면 `bids/<사업>/00_인테이크.md`를 서식(`intake.template.md`)에서 만들고 아래를 **한 묶음씩** 묻는다. 묶음 하나가 채워지면 파일에 적고 다음 묶음으로 간다. 사용자가 한 번에 여러 묶음을 주면 다 받아 적고 빈 것만 다시 묻는다.

| 묶음 | 묻는 것 | 받는 방식 | 없으면 |
|---|---|---|---|
| ⓪ 명령 인자 | **정확한 제안서명 · 용지(A4/A3) · 방향(횡/종)** | 첫 문장 「{제안서명} {A4\|A3} {횡\|종} 제안」에서 뽑는다. 빠진 것만 묻는다 | 문서 A4 종 · 덱 16:9 횡 기본. **RFP 작성 규칙에 용지·방향이 있으면 RFP가 이긴다**(한 줄 알림) |
| ① RFP | 제안요청서 원문(공고문·과업지시서·평가표 포함) | 노션 「📄 RFP 원문(추출)」 링크 · 파일 경로(pdf·hwp·docx) · 본문 붙여넣기 | **진행하지 않는다.** 「RFP 원문을 주십시오. 세 가지 중 편한 방법으로」를 다시 요구 |
| ② 연결 | 노션(재료 팩·위키) · 피그마(회사 계정·라이브러리) | P-1 ②에서 확인한 값. 노션이 안 되면 재료 팩을 사용자가 직접 붙여넣기(`material-pack.template.md`) | 노션 없음 → 팩 직접 제공으로 대체 가능. 피그마 없음 → P0~P5는 진행, 덱 게이트에서 다시 요구 |
| ③ 방향 | **사용자가 말로 주는 주요 방향** 한두 문장 · 꼭 넣을 것 · 하지 말 것 · 예산·인력 제약 · 발표 유무 | 대화 | 「방향 한 줄이 없으면 우리가 정해 드리고 동의를 받습니다」 — P3.5에서 후보 셋을 내고 택일 |
| ④ 재료 | 이전 제안서(같은 발주처·유사 과업) · 담당자 통화·현장 설명회 메모 · 발주처 만난 사람 · 예상 경쟁사 · 현장 사진·우리 실물 사진의 위치 | 파일·링크·「없음」 | 「없음」도 답이다. 적어 두고 P6 재료점검에서 다시 센다 |
| ⑤ 확인 | 받은 것을 요약해 보이고 「이대로 시작합니다」 | 사용자 「예」 | 고칠 것 있으면 고치고 다시 확인 |

질문 문장은 `asking.md` §1·§5를 따른다(찾아본 뒤·왜 한 줄·답하기 쉬운 형태). 묶음 안에서 일곱을 넘기지 않는다.

## 2. 진행 중에도 묻는다

- 각 단계 끝에 `gap_check.py`가 결손을 세고, 초안 게이트·덱 게이트 앞에서 `readiness.py`가 남은 것을 **사용자에게 요구할 문장**으로 만든다. Claude는 그 문장을 다듬어 보낸다.
- 방향이 바뀌면(사용자가 P4 도중 「방향 바꾸자」) `00_인테이크.md` ③을 고치고 03b 방향 절을 다시 동의받은 뒤 이어 간다. 조용히 바꾸지 않는다.
- 사용자가 「그냥 진행해」라고 하면: 게이트 항목 중 **RFP·피그마 연결·승인**은 예외 없이 필요하다고 답하고, 나머지는 「사용자 결정으로 건너뜀(일시)」을 인테이크에 적고 진행한다. 건너뛴 항목은 초안·덱에 `⚠️ 확인필요`로 남는다.

## 3. `00_인테이크.md` 서식은 `intake.template.md`

체크 상자 `[x]`와 값을 Claude가 채운다. `readiness.py`는 이 파일의 체크·값과 폴더의 산출물(00_RFP원문_추출 · 01 · 02 · 03 · 03a · 03b · 04 · 05 · 06/07 · `_STATE.md` 준비점검·승인)을 함께 본다. 인테이크만 체크하고 산출물이 없으면 통과하지 않는다.

## 4. 헤드리스(`claude -p`)

접수는 사람이 앉은 세션에서만 한다. 헤드리스에서 인테이크가 비어 있으면 `차단사항`에 「접수 미완 — 대화형 세션에서 `/bid-loop <사업>`」을 적고 종료한다.
