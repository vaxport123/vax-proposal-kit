# /bid-loop — 1회 호출 = 1스텝

## 인자

```
$ARGUMENTS
```

위 값이 이번 호출의 대상이다. 비어 있으면 현황 조회 모드다(부팅 1 참조).
도구 권한은 `.claude/settings.json`의 `permissions.allow`로 관리한다.

> **파일명 주의**: 반드시 `bid-loop.md`로 저장한다. `loop.md`로 저장하면 Claude Code 내장 `/loop`를 덮어쓴다.

## 절대 규칙
1. **한 번 호출에 한 스텝만.** 스텝을 끝내면 `_STATE.md`를 갱신하고 즉시 종료한다. 이 규칙이 토큰 소진 시 손실을 1스텝으로 제한한다.
2. **첫 동작은 `_STATE.md` 읽기.** 상태파일이 진실의 원천이다. 대화 기억에 의존하지 않는다.
3. **스텝 시작 전 `진행중: true`, 끝나면 `false`.** 켜진 채로 발견되면 이전 세션이 끊긴 것이니 그 스텝을 처음부터 재실행한다.
4. **게이트는 문서로 증명하지 못하면 통과가 아니다.**
5. **작업 시간대 검사는 `run-loop.sh`가 맡는다.** 대화형 직접 호출은 시간 제약이 없다.
6. **헤드리스에서는 절대 사용자 입력을 기다리지 않는다.** 질문이 필요하면 `차단사항`에 적고 즉시 종료한다.
7. **회사 상수(신용등급·업종코드·직접생산확인·설립일)는 재료 팩 §5에서만 읽는다.** 이 파일에도, 어느 규칙 파일에도 적지 않는다(2026-09-05: 옛 판에 박혀 있던 값을 지웠다. 위키가 바뀌면 재료 팩이 먼저 바뀐다).

## 부팅
```
1) 인자가 폴더명이면  → bids/{인자}/_STATE.md 읽기
   인자가 공고번호면  → SKILL.md P0대로 재료 팩을 읽고 bids/{사업명}/ 생성 · _STATE.md 초기화 → P1
   인자가 없으면      → bids/ 스캔 → `완료` 아닌 사업과 각 `다음행동`을 표로 출력하고 종료
2) `진행중: true`      → "이전 세션 중단 감지, {단계} 재실행" 출력 후 그 단계 처음부터
3) `차단사항`이 비어 있지 않으면 → 내용 출력 후 종료(대화형이면 해제 여부를 묻고, 헤드리스면 묻지 않고 종료)
4) `다음행동`에 적힌 스텝으로 분기
```

## 스텝 — 내용은 `skills/vax-proposal/SKILL.md`, 여기는 산출물과 출구만
| 스텝 | 산출물 | 출구 → 다음행동 |
|---|---|---|
| P0 재료 팩 | `00_RFP원문_추출.md` · `_STATE.md` | 재료 팩 열 절 확인 → P1. 없으면 차단사항 |
| P1 평가표 | `01_평가표.md` (§7 작성 규칙 · §8 요구 ID·품목) | 배점 합 100 → P2 |
| P2 가점 · 게이트 ① | `02_가점진단.md` | 실점 ≤ 5 → P3 · 정성 ≥ 70%면 사용자 판단 · 아니면 중단(가점미달). 회복가능 실점은 차단사항에 기한과 함께 |
| P3 레퍼런스 | `03_레퍼런스매핑.md` | 매칭 ≥ 3 AND 공백 ≤ 1/3 → P3.5 · 2회 연속 미달은 보고 후 종료 |
| P3.5 페인포인트·색채·방향 | `03a_페인포인트.md`(웹 조사 · 출처) · `03b_방향전략.md`(색채 카드 · 아이디어 교차표 · 방향 · 전략) | 페인포인트 5~8 · 카드 8~15 · 아이디어 3 → 방향에 사용자 동의 → P4-초안. 헤드리스면 방향을 차단사항에 적고 종료 |
| P4-초안 | `04_제안서_v1.md` | → P4-검토1 |
| P4-검토N (1~3) | `logs/lint_N.txt`(`proposal_lint.py`) · `04_제안서_v{N+1}.md` · `logs/검토N.md` · `logs/비판_N.md` | lint 「상」 0 AND 누락 → 증거 → 차별성(+비판자) · 3회 완료 → P5 |
| P5 심사 · 게이트 ② | `05_심사결과_N.md` | ≥ 80 → P6-계획 · < 80이고 재작성 0회 → P4-재작성(상위 3건만) · 1회면 중단(심사미달) |
| P6-재료 | `06_재료점검.md`(결정 한 문장 · 반대 셋 · 발주처 사진 6 · 우리 실물 6 · 숫자 5 · 카드 8) | 빈 칸 0 → P6-계획. 빈 칸이 있으면 **재료 요청서**를 `차단사항`에 적고 종료(덱을 만들지 않는다) |
| P6-계획 | `07_슬라이드계획_v1.md`(고스트 덱: 액션 타이틀 · 증거 유형 · 증거 출처 · 대응표 · 반대 의견 · 리듬 · 브리프) → `proposal_lint.py --plan` → 비판자(deck) → `v2` | lint 「상」 0(재료 점검 절 · 증거 열 · 증거 빈칸 · 대응표 빈칸) → **사람 승인** → P6-시안. **여기서부터 Figma MCP가 필요해 헤드리스로는 못 간다** — 차단사항에 「사람 세션에서 P6-시안」 |
| P6-시안 | Figma 파일 + 가장 밀도 높은 본문 장 1장 + `shots/시안.png` | 사용자 확인 → P6-제작. 헤드리스면 시안 링크를 차단사항에 적고 종료 |
| P6-제작 | Figma 덱 (PART 행 단위로 한 스텝에 한두 행 · 행마다 `validate()` clean) | `_STATE.md`에 `P6-제작(Ⅲ부터)`처럼 재개 지점 → 전 행 완료 → P6-검사 |
| P6-검사 | `shots/` 전 장 PNG · `logs/비판_덱.md` | 비판자 지시 반영 → `상태: 완료` |

사업 폴더:
```
bids/{사업명}/
  _STATE.md  00_RFP원문_추출.md  01_평가표.md  02_가점진단.md  03_레퍼런스매핑.md  03a_페인포인트.md  03b_방향전략.md
  04_제안서_v1.md ~ v4.md  05_심사결과_1회.md  06_재료점검.md  06_제안서.html(선택)  07_슬라이드계획_v1.md ~
  figs/  img/(+MANIFEST.md)  ci/  shots/  logs/
```
`bids/`는 git에 넣지 않는다. `/bid-loop` 명령은 `install.sh`가 이 파일을 `~/.claude/commands/bid-loop.md`로 복사해 만든다.

## 스텝 종료 시 항상
```
1) _STATE.md 갱신: 현재단계 / 다음행동 / 진행중:false / 마지막갱신
2) logs/ 에 이번 스텝 요약 1~5줄 append
3) 사용자에게 3줄 보고: [완료한 것] [다음 스텝] [사람이 처리해야 할 차단사항]
4) 종료. 다음 스텝을 이어서 하지 않는다.
```

## 토큰 예산
스텝 진입 전 끝까지 갈 수 있을지 본다. 어렵다면 **시작하지 말고** `_STATE.md`에 재개 지점만 더 잘게 적고 종료한다. 반쯤 쓴 문서가 가장 비싼 실패다.
