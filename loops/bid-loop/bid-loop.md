# /bid-loop — 입찰 제안 파이프라인 (게이트 기반, 1회 호출 = 1스텝)

## 인자

```
$ARGUMENTS
```

위 값이 이번 호출의 대상이다. 비어 있으면 현황 조회 모드다. (0단계 참조)
도구 권한은 `.claude/settings.json`의 `permissions.allow`로 관리한다. 이 명령에서 별도로 제한하지 않는다.

> **파일명 주의**: 이 파일은 반드시 `bid-loop.md` 로 저장한다. `loop.md` 로 저장하면
> Claude Code 내장 `/loop` 스킬(세션 내 주기 반복 실행)을 덮어쓴다. 두 기능은 완전히 다르다.

## 절대 규칙

1. **한 번 호출에 한 스텝만 실행한다.** 스텝을 끝내면 `_STATE.md`를 갱신하고 즉시 종료한다.
   다음 스텝을 이어서 하지 않는다. 이 규칙이 토큰 소진 시 손실을 1스텝으로 제한한다.
2. **모든 작업의 첫 동작은 `_STATE.md` 읽기다.** 상태파일이 진실의 원천이다.
   대화 기억에 의존하지 않는다.
3. **스텝 시작 전에 `_STATE.md`의 `진행중` 플래그를 켜고, 끝나면 끈다.**
   플래그가 켜진 채로 발견되면 이전 세션이 중간에 끊긴 것이므로 그 스텝을 처음부터 재실행한다.
4. **게이트는 통과 조건을 문서로 증명하지 못하면 통과가 아니다.** 느낌으로 통과시키지 않는다.
5. **작업 시간대 검사는 실행 스크립트(`run-loop.sh`)가 담당한다.** 대화형으로 직접 호출한 경우는 시간 제약 없음.
6. **비대화형(headless) 실행에서는 절대 사용자 입력을 기다리지 않는다.**
   질문이 필요한 상황이면 `차단사항`에 질문을 적고 즉시 종료한다.
   새벽 3시에 물어보면 아무도 대답하지 않고 프로세스만 멈춘다.

## 0단계: 부팅

```
1) 인자가 폴더명이면      → bids/{인자}/_STATE.md 읽기
   인자가 RFP 파일이면    → bids/{사업명}/ 새로 생성, _STATE.md 초기화, P1으로 진입
   인자가 없으면          → bids/ 전체 스캔 → `완료` 아닌 사업 목록과 각 `다음행동` 을 표로 출력하고 종료
2) `진행중: true` 이면 → "이전 세션 중단 감지, {단계} 재실행" 출력 후 해당 단계 처음부터
3) `차단사항` 이 비어 있지 않으면 → 차단 내용 출력 후 종료 (대화형이면 해제 여부를 묻고, 비대화형이면 묻지 않고 종료)
4) `다음행동` 에 적힌 단계로 분기
```

프로젝트 폴더 구조:

```

  {사업명}/

    05_심사결과_1회.md      ← P5 산출물
```

## P1 — RFP 파싱

RFP 원문에서 다음을 **원문 표현 그대로** 추출해 `01_평가표.md`에 기록한다. 추측으로 채우지 않고,
찾을 수 없는 항목은 `[RFP에 명시 없음]`으로 표기한다.

- 사업명 / 발주기관 / 사업예산 / 사업기간 / 제안서 제출 마감일시
- 입찰방식 (협상에 의한 계약 / 일반경쟁 / 제한경쟁 등)
- **기술:가격 배점 비율**, 협상적격자 기준 점수
- **정량평가 배점표** (항목명 / 배점 / 만점 조건 / 증빙서류) — 한 줄도 빠뜨리지 않는다
- **정성평가 배점표** (항목명 / 배점 / 평가 착안점)
- 참가자격 (업종코드, 면허, 실적요건, 컨소시엄·하도급 허용 여부)
- 제안서 규격 (분량 제한, 서식, 목차 강제 여부, 발표 시간)
- 과업 범위 — 산출물 목록을 개수까지 명시해 옮긴다

**출구**: 정량·정성 배점 합이 100인지 검산. 맞지 않으면 누락이므로 재추출.
→ `다음행동: P2`

## P2 — 가점 진단 (게이트 ①)

`01_평가표.md`의 정량평가 항목마다 회사 정보를 대조해 실점을 계산한다.
회사 정보 출처는 프로젝트 파일(`VAX_COMPANY1~5.md`, 신용평가확인서, 경쟁입찰참가자격등록증)이며,
**파일에 근거가 없는 항목은 "확인필요"로 두고 실점을 0으로 가정하지 않는다.**

실점을 두 종류로 분류한다.

| 구분 | 정의 | 예 |
|---|---|---|
| **회복가능** | 마감 전 서류 발급·등록으로 0으로 만들 수 있음 | 업종코드 미등록, 중소기업확인서 만료, 직접생산확인서 누락 |
| **회복불가** | 이번 입찰에서 바꿀 수 없음 | 신용등급(B-), 부채비율, 최근 3년 매출액, 업력 |

`02_가점진단.md` 출력 형식:

```
| 정량항목 | 배점 | 백스포트 해당 | 획득 | 실점 | 구분 | 근거 |
```

**백스포트 상수 실점 주의**
- 신용등급 **B- (NICE D&B e-6-)** — 유효 2027.06.30. 신용등급 배점 항목에서 항상 실점 발생.
- **창업기업 특례 확인이 P2의 선행 조건이다.** 설립 2020.05.11 → 7년 이내.
  추정가격이 법정 기준 이하이고 특례 조항이 공고에 있으면 신용등급 배점은 만점 처리되거나 면제된다.
  공고문에서 "창업기업", "창업자", "소기업·소상공인" 조항을 검색해 확인하고, 불명확하면
  **발주기관 질의를 `차단사항`에 등록하고 종료한다.** 특례 여부를 모르는 상태로 게이트를 판정하지 않는다.
- 이미 등록된 업종코드(재확인 불필요): 1169 학술·연구용역 / 1426 패키지SW / 1468 컴퓨터관련서비스 /
  **1469 디지털콘텐츠개발** / **1470 데이터베이스제작및검색** / 3230 방송영상독립제작자 /
  3244 비디오물제작업 / 3245 게임제작업 / **4440 산업디자인전문회사(시각디자인)** /
  **4443 산업디자인전문회사(멀티미디어디자인)** / 9901·9902·9999 기타자유업
  → 등록증 갱신일 2026.07.24 기준. 그 이후 변동은 나라장터에서 재확인.
- 직접생산확인: 동영상제작서비스(8213160301) 유효 2027.09.17.

### 게이트 판정

```
실점합계 ≤ 5.0                              → 통과. 다음행동: P3
실점합계 > 5.0 AND 정성배점비중 ≥ 70%        → 사용자 판단 요청. 종료.
                                              (기술 90:가격 10 구조에서는 정량 실점이
                                               정성으로 역전 가능하므로 자동 폐기하지 않는다)
실점합계 > 5.0 AND 정성배점비중 < 70%        → 루프 정지. `상태: 중단(가점미달)` 기록.
                                              실점 원인과 회복가능 항목 처리방안을 보고하고 종료.
회복가능 실점이 있으면                        → 실점합계에는 포함하되, `차단사항`에
                                              마감 역산 처리 기한과 함께 등록한다.
```

`_STATE.md`의 `가점실점` 에 `합계 / 회복불가 / 회복가능` 세 값을 모두 기록한다.

## P3 — 레퍼런스 확보

`_REFERENCE_INDEX.md`를 먼저 읽는다. **`VAX_COMPANY5.md` 전문을 다시 읽지 않는다** — 색인이 그 역할을 한다.
색인에 없는 실적이 필요할 때만 원본을 부분 조회한다.

1. RFP 과업범위를 기술요소로 분해 (예: 포토그래메트리 / 볼류메트릭 / 실감전시 / AI디지털휴먼 / 3D맵핑 / XR플랫폼)
2. 기술요소마다 색인에서 실적을 매칭. 각 매칭에 **발주기관·사업비·기간·수행역할**을 붙인다
3. RFP가 요구하는 실적요건(건수·금액·기간)을 충족하는 조합을 명시
4. **약점도 기록한다.** 매칭되는 실적이 없는 기술요소는 `[레퍼런스 공백]`으로 표시하고,
   R&D 과제·특허·인력 이력 중 대체 근거를 찾는다. 없으면 그대로 공백으로 남긴다
5. 유사 제안서가 `bids/` 안에 있으면 재활용 가능한 챕터를 파일·섹션 단위로 지목

`03_레퍼런스매핑.md` 출력 형식:

```
| 기술요소 | 매칭실적 | 발주기관 | 사업비 | 강점 문구(그대로 제안서에 쓸 문장) |
```

**출구**: 매칭 실적 3건 이상 AND `[레퍼런스 공백]`이 전체 기술요소의 1/3 이하.
미달이면 P3 재실행(다른 각도로 재탐색). 2회 연속 미달이면 사용자에게 보고하고 종료.
→ `다음행동: P4-초안`

## P4 — 제안서 작성 (워드) + 비판검토 3회

**형식**: RFP가 요구하는 최종 형태와 무관하게 **초기 제안서는 항상 .docx**로 작성한다.
**docx 스킬을 먼저 불러 그 규칙을 따른다.** (`/plugin install document-skills@anthropic-agent-skills` 로 설치되어 있어야 한다.
프롬프트에 "docx 스킬을 사용해" 라고 명시한다. 스킬이 없으면 python-docx로 직접 생성하되, 목차·머리글·표 서식 품질이 떨어짐을 보고에 명시한다.)

### P4-초안

RFP 목차 강제가 있으면 그 목차를 그대로, 없으면 정성평가 항목 순서를 목차로 삼는다.
**정성평가 항목 1개 = 제안서 챕터 1개** 원칙. 평가위원이 채점표와 제안서를 나란히 볼 수 있게 한다.

`03_레퍼런스매핑.md`의 강점 문구를 해당 챕터에 배치한다. 강점 나열이 아니라
**"RFP가 요구하는 특징 → 우리 레퍼런스가 그것을 이미 해봤다는 증거"** 구조로 쓴다.

분량이 커서 한 스텝에 못 끝내면 **챕터 단위로 분할**한다.
`_STATE.md`의 `다음행동`에 `P4-초안(3장부터)`처럼 재개 지점을 남기고 종료한다.

산출: `04_제안서_v1.docx` → `다음행동: P4-검토1`

### P4-검토N (N = 1, 2, 3)

세 회차의 관점을 **다르게** 둔다. 같은 지적을 세 번 반복하는 것은 검토가 아니다.

| 회차 | 관점 | 찾아야 하는 것 |
|---|---|---|
| 1 | **누락** | 정성평가 항목 중 대응 챕터가 없거나 얕은 곳. 과업범위 산출물 중 언급 안 된 것 |
| 2 | **증거** | 주장에 근거(실적·수치·특허·인력)가 붙지 않은 문장. "최적의", "차별화된" 같은 무근거 수식어 |
| 3 | **차별성** | 경쟁사도 똑같이 쓸 수 있는 문장. 백스포트만 쓸 수 있는 문장으로 교체 |

각 회차는 `04_제안서_v{N+1}.docx`를 새로 만든다. 원본을 덮어쓰지 않는다.
지적사항과 반영 결과를 `logs/검토{N}.md`에 남긴다.

3회 완료 → `다음행동: P5`

## P5 — 심사위원 채점 (게이트 ②)

`_REVIEW_RUBRIC.md`를 읽고 그 절차를 따른다. 핵심 규칙:

- 페르소나를 고정한다: **해당 분야 심사 3회 이상, 유사 제안서 20건 이상 검토한 학계 위원.**
  제안서 작성자의 시선을 버린다.
- **감점 사유를 먼저 전부 쓴 뒤에 점수를 매긴다.** 점수를 먼저 정하고 사유를 붙이면 무조건 후해진다.
- 항목 점수마다 **제안서 내 근거 위치(장·절)를 인용한다. 인용 못 하면 그 항목은 0점.**
- 배점은 `01_평가표.md`의 실제 정성 배점표를 100점 환산해 사용한다.

산출: `05_심사결과_{회차}.md` — 항목별 점수 / 감점사유 / 근거위치 / 총점 / 상위 개선 3건

### 게이트 판정

```
총점 ≥ 80                       → 통과. 다음행동: P6-1
총점 < 80 AND 재작성횟수 == 0    → 재작성 1회. 다음행동: P4-재작성
                                  (감점사유 상위 3건만 겨냥해 수정. 전면 재작성 금지)
총점 < 80 AND 재작성횟수 == 1    → 루프 정지. `상태: 중단(심사미달)`.
                                  미달 항목·원인·판단 필요 사항 보고 후 종료.
                                  ※ 무한루프 방지. 2회차 미달은 사람이 판단한다.
```

## P6 — 발표자료 (PPT)

**pptx 스킬을 먼저 불러 그 규칙을 따른다.** (document-skills 플러그인 필요. 없으면 python-pptx로 직접 생성.)

1. 최초 진입 시 전체 슬라이드 구성표를 `06_구성표.md`로 만든다 (총 페이지 수 확정)
2. **한 스텝에 최대 5페이지.** 예: 50페이지면 10스텝.
3. 스텝마다 `_STATE.md`에 `P6-{다음 시작 페이지}` 기록 후 종료
4. 전 페이지 완료 → `상태: 완료`

## 스텝 종료 시 항상 할 일

```
1) _STATE.md 갱신: 현재단계 / 다음행동 / 진행중:false / 마지막갱신(date 출력값)
2) logs/ 에 이번 스텝 요약 1~5줄 append
3) 사용자에게 3줄 보고: [완료한 것] [다음 스텝] [사람이 처리해야 할 차단사항]
4) 종료. 다음 스텝을 이어서 하지 않는다.
```

## 토큰 예산 판단

스텝 진입 전, 그 스텝을 끝까지 갈 수 있을지 판단한다. 어렵다고 보이면
**작업을 시작하지 말고** `_STATE.md`에 재개 지점만 더 잘게 쪼개 기록하고 종료한다.
반쯤 쓴 문서를 남기는 것이 가장 비싼 실패다.
