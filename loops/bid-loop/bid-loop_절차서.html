STEP 0

사전 확인 — Claude Code가 있는가

3분

터미널(macOS: 터미널 앱 / Windows: PowerShell)을 열고 버전을 확인합니다.

claude --version
# 버전 번호가 나오면 통과. "command not found" 면 설치:
npm install -g @anthropic-ai/claude-code
claude          # 최초 실행 시 브라우저 로그인 창이 뜬다 → 로그인 → /exit 로 종료
npm이 없다면 — Node.js가 먼저 필요합니다. nodejs.org에서 LTS를 설치한 뒤 위 명령을 다시 실행하십시오.
STEP 1

프로젝트 폴더 만들기

2분

입찰 작업 전용 폴더를 만듭니다. 위치는 자유이고, 아래는 홈 디렉터리 기준 예시입니다. 이후 모든 명령은 이 폴더 안에서 실행합니다.

mkdir -p ~/bids-project
cd ~/bids-project
mkdir -p .claude/commands bids logs company
폴더들어갈 것
.claude/commands/bid-loop.md (명령어 정의)
bids/사업별 폴더 + 공용 색인·채점기준
company/VAX_COMPANY1~5.md, 신용평가확인서, 등록증 (P2가 대조하는 원본)
logs/야간 실행 로그 (자동 생성)
STEP 2

cd ~/bids-project

STEP 3

문서 스킬 설치 — 워드·PPT 품질이 여기서 갈린다

5분

P4(워드 제안서)와 P6(PPT)의 산출물 품질은 Anthropic 문서 스킬에 달려 있습니다. Claude Code에는 기본 포함되어 있지 않아 플러그인으로 설치합니다. Claude Code를 실행한 상태에서 아래 두 명령을 순서대로 입력합니다.

cd ~/bids-project
claude
# Claude Code 프롬프트 안에서:
/plugin marketplace add anthropics/skills
/plugin install document-skills@anthropic-agent-skills

설치가 끝나면 그 자리에서 바로 검증합니다.

# Claude Code 프롬프트 안에서:
docx 스킬을 사용해서 "설치 테스트"라는 제목의 한 페이지 워드 문서를 test.docx 로 만들어줘
설치가 안 되는 환경이라면 — bid-loop.md에 대체 경로가 이미 들어 있습니다. 스킬이 없으면 python-docx / python-pptx로 직접 생성하되 서식 품질 저하를 보고하게 되어 있으니, 파이프라인이 멈추지는 않습니다.
STEP 4

첫 실행 — RFP 투입과 P1

10분

나라장터에서 공고문(제안요청서) PDF를 내려받아 bids/에 넣습니다. 이 부분은 자동화되지 않습니다 — 나라장터 로그인 영역에는 Claude가 들어가지 못하므로, RFP 파일을 가져다 놓는 것까지가 사람의 일입니다.

cp ~/Downloads/제안요청서_몽골유적.pdf  ~/bids-project/bids/
cd ~/bids-project
claude
# Claude Code 프롬프트 안에서. / 를 입력하면 자동완성 목록에 bid-loop 이 보여야 한다:
/bid-loop bids/제안요청서_몽골유적.pdf

이 한 번의 호출로 일어나는 일: 사업 폴더 생성 → 상태파일 초기화 → P1 (RFP 파싱) 실행 → 상태파일 갱신 → 3줄 보고 후 종료. 1회 호출 = 1스텝이므로 여기서 멈추는 것이 정상입니다.

# 끝났을 때 이런 형태의 보고가 나온다:
[완료] P1 — 배점표·참가자격·과업범위 추출 → bids/몽골유적/01_평가표.md
[다음] P2 — 가점 진단 (다시 /bid-loop 몽골유적 호출 시 실행)
[차단사항] 없음

산출물을 직접 검사한다 — 이 단계가 제일 중요합니다

bids/몽골유적/01_평가표.md를 열고 공고문 원문과 대조하십시오. 배점표 숫자가 하나라도 틀리면 이후 모든 게이트 판정이 틀립니다.

  • 정량 + 정성 배점 합이 100인가
  • 기술:가격 비율, 협상적격 기준점수가 공고문과 일치하는가
  • 참가자격의 업종코드·실적요건이 빠짐없이 옮겨졌는가
  • 찾지 못한 항목이 [RFP에 명시 없음]으로 정직하게 표시되어 있는가 (추측으로 채워져 있으면 그 자체가 경고 신호)
자동완성에 bid-loop이 안 뜨면 — Claude Code를 프로젝트 폴더 밖에서 실행한 경우입니다. /exit 후 cd ~/bids-project && claude로 다시 여십시오. 프로젝트 명령은 그 프로젝트 폴더 안에서만 보입니다.
STEP 5

게이트 ① — P2 가점 진단 돌려보기

10분

같은 명령을 한 번 더 부릅니다. 상태파일의 다음행동: P2를 읽고 이번에는 가점 진단이 실행됩니다.

/bid-loop 몽골유적

P2는 company/의 회사 정보와 정량평가표를 대조해 실점을 계산하고, 회복가능 / 회복불가로 나눕니다. 결과는 02_가점진단.md에 표로 남습니다.

판정 읽는 법 — 세 갈래

보고 내용의미당신이 할 일
통과 → 다음행동: P3실점 합계 ≤ 5.0없음. 계속 호출하거나 야간 자동화로 넘긴다
사용자 판단 요청실점 > 5이지만 정성 배점 비중 ≥ 70% — 기술 90:가격 10 구조에선 정량 실점이 정성으로 역전 가능02_가점진단.md를 읽고 진행 여부를 결정, _STATE.md의 다음행동을 직접 P3로 수정하거나 상태: 중단으로 기록
중단(가점미달)실점 > 5이고 정성 비중도 낮음보고된 실점 원인 확인. 회복가능 항목(서류·등록)이 있으면 처리 후 상태파일의 상태를 진행중으로 되돌려 재실행
차단사항이 등록되며 멈출 수도 있습니다. 예: "창업기업 특례 적용 여부 발주기관 질의 필요". 이건 오류가 아니라 설계입니다 — 특례 적용 여부를 모르는 채 신용등급 B- 실점을 판정하면 안 되기 때문입니다. 질의 회신을 받은 뒤 _STATE.md의 차단사항 항목을 지우고 창업기업특례: 값을 적용 또는 미적용으로 채우면 다음 호출에서 이어집니다.

STEP 7

야간 자동화 — 21시부터 아침 9시까지

10분 설정

대화형으로 P2 게이트까지 통과시킨 뒤에 자동화를 거십시오. 검증 안 된 파이프라인을 밤에 풀어놓는 것이 가장 비싼 실수입니다. 두 경로 중 하나를 고릅니다.

경로 A · 간단

Desktop Scheduled Tasks

Claude Code 데스크톱 앱 사이드바의 Scheduled 메뉴 → 새 작업 생성.

• 프롬프트: /bid-loop 몽골유적
• 작업 폴더: ~/bids-project
• 주기: 매시 (시간대 검사는 명령어 안에서 하지 않으므로, 앱에서 시간 지정이 가능하면 21~08시로 제한)

GUI라 설정이 쉽지만, 스텝당 비용 상한과 중복 실행 잠금은 없습니다.

경로 B · 권장

run-loop.sh + cron

시간대(21~09시)·중복 실행 잠금·스텝당 예산 상한(--max-budget-usd)·30분 타임아웃·로그를 스크립트가 전부 통제합니다.

"비용 과다 계상 방지" 요건을 확실히 충족하는 쪽은 이쪽입니다.

경로 B 설정

# 1) claude 실행파일의 절대경로 확인 (cron은 PATH가 빈약하다)
which claude
/usr/local/bin/claude   ← 이 값을 기억

# 2) 먼저 손으로 한 번 돌려본다 (21시 이전이면 조용히 종료되는 게 정상 —
    시간대 무시하고 테스트하려면 스크립트의 시간대 검사 4줄을 잠시 주석 처리)
cd ~/bids-project
./run-loop.sh 몽골유적
cat logs/loop-$(date +%Y%m%d).log

# 3) crontab 등록 — 매시 정각. 시간대는 스크립트가 거른다
crontab -e
# crontab 편집기에 한 줄 추가 (경로는 자신의 것으로):
0 * * * * /Users/vax/bids-project/run-loop.sh 몽골유적

예산·시간 상한을 바꾸려면 환경변수로 줍니다: MAX_BUDGET_USD=1 ./run-loop.sh 몽골유적 (기본 3달러/스텝, 30분 타임아웃, 60턴).

토큰·사용량이 소진되면 — 그 시각의 실행은 실패로 로그에 남고 아무것도 망가지지 않습니다. 다음 정각에 cron이 다시 부르고, 재개 지점은 _STATE.md가 알고 있습니다. "충전 후 일정에 맞게 재시작"은 이 두 부품(cron + 상태파일)의 합으로 구현됩니다.
Windows라면 — cron 대신 작업 스케줄러: schtasks /create /tn "bid-loop" /sc hourly /tr "wsl bash /home/vax/bids-project/run-loop.sh 몽골유적" (WSL 기준). run-loop.sh는 bash 스크립트이므로 WSL 또는 Git Bash가 필요합니다.

문제 해결

증상원인조치
/bid-loop이 자동완성에 없다프로젝트 폴더 밖에서 실행 / 파일 위치 오류cd ~/bids-project 후 재실행. .claude/commands/bid-loop.md 경로 확인
내장 /loop이 사라졌다파일을 loop.md로 저장해 내장 스킬을 덮어씀bid-loop.md로 개명
cron이 도는데 아무 일도 안 생긴다① 21~09시 밖 (정상) ② claude 경로 문제①은 정상. ②는 로그에 오류가 남으니 CLAUDE_BIN=/절대경로를 crontab 줄 앞에 추가
실행이 30분에서 끊긴다 (TIMEOUT)한 스텝이 너무 큼정상 방어 동작. 다음 정각에 이어서 시도한다. 반복되면 _STATE.md의 다음행동을 더 잘게 (예: P4-초안(2장만)) 직접 수정
docx가 이상하게 생성된다document-skills 미설치STEP 3 재실행. 프롬프트에 "docx 스킬을 사용해"가 들어가는지 확인
같은 스텝을 반복한다이전 세션이 진행중: true를 못 끄고 죽음정상 — 그 스텝을 처음부터 재실행하는 설계다. 3회 이상 반복되면 스텝이 너무 크다는 뜻이므로 위 TIMEOUT 조치와 동일
