# examples/ — 이름을 가린 완성 예시 한 세트

`bids/`는 git에 넣지 않으므로 새 사용자가 볼 「끝까지 간 사업 폴더」가 저장소에 없었다(2026-09-05 리뷰에서 지적). 이 폴더가 그 자리를 채운다.

**전부 가상이다.** 발주처 「예시광역시 예시문화재단」, 공고번호 `R26EX00000001`, 수치·실적·인명·특허 번호는 서식을 보여 주기 위해 지어낸 값이다.
실제 사업에서는 이 자리에 **재료 팩과 위키에서 온 값만** 들어간다. 여기 값을 복사해 쓰면 그것이 곧 「없는 실적을 적는」 사고다.

## 파일 순서 (SKILL.md P0~P6 그대로)
| 파일 | 단계 | 이 예시에서 보여 주는 것 |
|---|---|---|
| `_STATE.md` | 운행 | 상태 기계. `다음행동`으로 분기한다 |
| `01_평가표.md` | P1 | 배점표 검산 · §7 제안서 작성 규칙(RFP에서 뽑은 것) · §8 요구 ID·품목 번호 |
| `02_가점진단.md` | P2 게이트 ① | 실점을 회복가능/회복불가로 나눈 표 |
| `03_레퍼런스매핑.md` | P3 | 기술요소 ↔ 실적 ↔ 그대로 쓸 문장 · 공백 |
| `03a_페인포인트.md` | P3.5 | **RFP 문장 ↔ 웹에서 확인한 사실(출처·날짜) ↔ 숨은 필요 ↔ 배점 연결** |
| `03b_방향전략.md` | P3.5 | **색채 카드(경쟁사가 못 쓰는 이유) · 페인포인트 × 카드 교차표 · 돈→안 할 것→할 것→강점 · 컨셉·차별점** |
| `04_제안서_v1.md` | P4 | Ⅰ장 한 장만. 문단 아래 ```fig 블록 · 출처 [n] · 끝의 확인필요 목록. `proposal_lint.py`를 통과한다 |
| `05_심사결과_1회.md` | P5 게이트 ② | 감점 사유 먼저 → 점수 → 근거 위치 인용 |
| `07_슬라이드계획_v1.md` | P6 | **디자인 브리프 · 제목 사슬 · 장별 표(유형·도식·사진·초안 문단 번호) · RFP 대응표**. `proposal_lint.py --plan`을 통과한다 |
| `logs/비판_1.md` | P4 ④ | 비판자 발견 표의 모양 |

## 검사해 보기

```bash
python3 skills/vax-proposal/scripts/proposal_lint.py examples/예시문화재단_실감콘텐츠/04_제안서_v1.md
python3 skills/vax-proposal/scripts/proposal_lint.py examples/예시문화재단_실감콘텐츠/07_슬라이드계획_v1.md --plan
python3 skills/vax-proposal/scripts/figures_svg.py examples/예시문화재단_실감콘텐츠/04_제안서_v1.md --list
```
셋 다 「상」 0이어야 한다. 규칙을 바꾸면 이 예시도 같이 고쳐 검사가 계속 통과하게 한다 — 예시가 곧 회귀 테스트다.
